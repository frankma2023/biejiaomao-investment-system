# 个股健康体检报告 Skill

## 0. 定位与铁律

本 skill 把"个股尽调"组织成一条**有主持人的决策流水线**：机器先定盘 → 九大师单向投票 → 主持人终裁输出动作。
**铁律（违反即不合格）**：
1. **裁决协议是输出结构**：必须落到"五档评级 + 动作清单（建仓区/止损/目标/失效条件/下次体检触发点）"，不允许只给一堆平行观点。
2. **九大师每人必须投"买/等/回避"单向票**（奇数 9 人，结构性避免平局）+ 一句基于数据的理由。禁止自由发挥长文。观点不同可以，但都要表态。
   **九个视角各管一件事，不要串味**：欧奈尔看买点与CANSLIM、威科夫看吸筹派发、利弗莫尔看趋势关键点、段永平看生意与能力圈、巴菲特看护城河与资本配置、芒格看逆向风险、索罗斯看反身性周期、**Oliver Kell 只看价格行为（不看基本面）**、**Mauboussin 只反推价格隐含预期（不判公司好坏）**。
2.1 **禁止只投否定票**：每位大师在给出「等/回避」后，必须再用可量化数值回答「满足什么条件我会改投买」（见 §步骤 9.5）。只给「等估值合理」这类无法执行的套话 = 不合格。
3. **数据不可编造**：确定性数据必须来自 `scripts/collect_data.py`（本地库）或本机 API；外部信息（行业/公告/业务占比/前瞻）用 web_search 且标注来源。缺的数据明说"未获取"，不得伪装。
4. **理解优先**：写不出"一句话业务定位 + 收入/毛利占比"之前，不许进入估值与投票环节（能力圈闸门）。
5. **红涨绿跌**：HTML 中涨/买/看好=#ef4444 红系，跌/卖/风险=#10b981 绿系。

## 1. 工作流（严格按序）

### 步骤 0 · 市场闸门
查本地 market-scan 数据：大盘趋势（追盘日/抛盘日）、风险级别。输出一行环境判断（顺风/逆风/中性），并说明它对仓位的影响。数据源：`http://localhost:8788/api/market-scan` 系 API。

### 步骤 1 · 数据拉取
运行：`python scripts/collect_data.py <CODE> --detail`（detail 模式含均线全系/MACD/KDJ/RSI/BOLL/量能/支撑压力/近15日K线 + 财务评估六卡实际输出）。
然后 web_search 补齐外部信息：行业最新动态、近期公告/财报要点、业务分部数据、可比公司、有无重大新闻。搜索不超过 4 次，聚焦"业务结构 + 行业格局 + 边际变化"。

#### 步骤 1.5 · **财报新鲜度检查（硬门槛，2026-10-30 新增）**

**在动笔写任何结论之前，必须确认该股的最新财报是否已入库。
**「我的库里没有」不等于「公司没发」。**

**背景（真实事故）**：分析中远海控 601919 时，本地库中该股最新季度仅到 2026-06-30，
而全库已有 3,627 只股票更新至 2026-09-30。报告据此得出「周期下行中段、TTM 同比 −46%」的结论并交付；
用户提醒后补拉 Q3，数据显示**单季净利 172.3 亿、同比 +80.7%、环比 +128.5%**，
TTM 同比从 −46% 收窄至 −8.2%——**结论从「无人投买」翻转为「芒格转买」。**

##### 检查方法（每次报告必做）

`sql
-- 1) 全库最新报告期是什么？
SELECT MAX(report_date) FROM stock_financials_quarterly;

-- 2) 该股最新报告期是什么？
SELECT MAX(report_date) FROM stock_financials_quarterly WHERE stock_code='<CODE>';

-- 3) 两者是否一致？若有差距，再看全库有多少股票已更新到最新期
SELECT COUNT(*) FROM stock_financials_quarterly WHERE report_date='<全库最新期>';
`

**判定：**

| 情形 | 处理 |
| :--- | :--- |
| 该股最新期 = 全库最新期 | ✅ 通过 |
| 该股落后，且全库已有数百只以上更新到最新期 | ⚠ **该股数据缺失，必须补拉后再分析** |
| 该股落后，全库几乎无股票更新到该期 | ✅ 该期尚未进入披露高峰，可接受 |

##### 补拉方法（定向，不跑全市场）

**不要运行 scripts/fetch_stock_financials.py 的全量模式**——它会重拉 5,684 只股票的全部历史期，耗时数小时。
**用定向补拉：**

`python
from fetch_stock_financials import api_post, QUARTERLY_METRICS
payload = {'date': 'latest', 'stockCodes': ['<CODE>'],
           'metricsList': [m[0] for m in QUARTERLY_METRICS]}
r = api_post('/company/fs/non_financial', payload)
# 返回是 list；每条含 date / reportDate / q.ps.* / q.m.* 嵌套结构
`

**注意三个坑：**
1. **API 路径是 /company/fs/non_financial**（不是 /cn/company/fundamental/...）
2. **参数名是 stockCodes**（不是 codes）
3. **返回值直接是 list**，不是 {data: [...]}

**补拉后必须重算所有依赖季度数据的指标**：TTM（FCF / 净利 / 扣非）、现金含量、PE、CANSLIM 的 A 项。

##### 报告里必须声明

**报告的「数据缺口」表中增加一行「财报新鲜度」，写明该股最新报告期与全库最新期是否一致。**
若曾补拉，须在正文中说明补拉了哪一期。

### 步骤 2 · 否决筛查（先确认不会死）
- ST/退市/上市状态（快照 §2）、质押爆仓风险、重大造假/失信历史（搜索确认）
- **致命项命中 → 直接输出"回避"报告**，不再做后续层（可简要说明否决理由）。

### 步骤 3 · 认识它（理解层，硬门槛）
- **一句话业务定位**：这公司靠什么赚钱（≤30 字，如"成本曲线最左端的 MDI 全球寡头，聚氨酯-石化-精细三链一体"）。写不出 = 能力圈外 → 输出"回避/看不懂不投"。
- **收入与毛利结构占比**（按业务分部，近 2 年变化——哪块在长大/萎缩）
- **商业模式类型**：周期制造/成长消费/收租平台/项目制等 + 盈利稳定性特征
- **管理层资本配置历史**：近 5 年资本开支方向、分红/回购记录、ROIC 趋势（快照 §6 年度财务可支撑）

### 步骤 4 · 行业卡
- 行业生命周期与景气位置（周期复苏中段/顶部/底部？）
- 竞争格局与集中度：公司在食物链位置（老大/老二/边缘），护城河来源
- 行业驱动因素与 12-24 个月前瞻（供需/价格/政策/技术）

### 步骤 5 · 评估它（财务验证 + 行业校准）
- 用快照 §5/§6：营收/净利/毛利率的季度与年度趋势、TTM 滚动同比、**二阶导（加速度）**——加速/减速？
- 财务健康：负债率/有息/周转，**必须对照行业特征校准**（同一阈值不适用所有行业；应收周转高不一定是坏事要看行业）
- 盈利质量（comps/quality 卡）：扣非占比、现金含量、FCF 与净利缺口（应收存货扩张要警惕）

### 步骤 6 · 定价它（估值构成拆解，禁止只报分位）
- 多周期分位：快照 §4 的 3/5/10 年分位直接引用（PE/PB/PS/股息率）
- **估值构成推算（核心）**：当前价格隐含了什么预期？方法：
  - 反推公允 PE：无风险利率(≈1.7%) + 股权风险溢价(≈5%) → 公允 PE ≈ 15x；与当前对比
  - 隐含增长：当前 PE ÷ (1/公允基准) 意味着市场定价了多少增长/周期恢复
  - 周期位置修正：周期股盈利低谷的"低 PE"可能是陷阱（盈利顶给最低 PE），要说明当前 PE 对应盈利的周期位置
- 一句话定价结论："现价已包含 XX 预期，贵/合理/便宜是因为 XX"

### 步骤 6.5 · 预期反推（Mauboussin 的证据基础）

**目的：不判断贵/便宜，而是反推「当前价格已经假设了什么」，再与基本面趋势对照。**

**方法一：反推隐含增长率**

隐含增长率 g = WACC − 1/PE

用 WACC ≈ 10%（无风险 1.7% + 股权风险溢价 5% + 周期/小盘溢价约 3%）：
- PE = 12.86 → 1/PE = 7.78% → g = 10% − 7.78% = 2.2%/年
- 若自身近 3 年净利 CAGR 为 −8%，则价格隐含的 +2.2% 增长明显偏乐观 → 偏回避

**方法二：与自身历史对照判方向**

| 对照 | 含义 | 票 |
| :--- | :--- | :--- |
| 隐含 g < 自身近 3 年 CAGR | 预期偏低 | 买 |
| 隐含 g ≈ 自身 CAGR（±2pp） | 预期已定价 | 等 |
| 隐含 g > 自身 CAGR | 预期偏高 | 回避 |

**方法三：ROIC vs WACC（增长是否创造价值）**

价值创造 = ROIC − WACC

- ROIC > WACC：增长创造价值，可给估值溢价
- ROIC < WACC：增长毁灭价值，增长率越高越该压低估值

**数据来源**：PE 取快照 §4；近 3 年 CAGR 取 §6 年度财务；
ROIC 可用 净利 /（有息负债 + 股东权益）粗算，**算不出时明说「未获取」，不得臆造**。

**必须输出**：隐含 g、自身 3 年 CAGR、二者差（pp）、ROIC vs WACC 判断、一句话结论（预期偏高／合理／偏低）。

### 步骤 7.5 · CPA 阶段（Oliver Kell 的证据基础）——**必须读引擎，不许手判**

**本项目已有 CPA 判定引擎，全市场每日扫描、结果已入库。Oliver Kell 的票必须建立在引擎输出上，禁止自己用均线/量能「估」一个阶段。**

#### 数据源（按标的类型选表）

| 标的 | 表 | 关键字段 |
| :--- | :--- | :--- |
| **个股** | `cpa_stage_daily` | `stage`、`prior_stage`、`days_in_stage`、`stage_start_date`、`action`、`structure_support`、`invalid_level`、**`metrics_json`（内含 `six_dir`/`vr`/`ema10`/`ema20`）** |
| **指数** | `index_cpa_daily` | `stage`、`stage_name`、`days_in_stage`、`since_date`、`action` |
| 个股周线 | `cpa_stage_stock_weekly` | 同上（多周期共振用） |

**引擎实现**：`src/scanners/cpa_index.py` 的 `run_state_machine(o,h,l,c,v)`，个股与指数通用（只吃 OHLCV）。

**查询示例（个股）**：

```sql
SELECT stage, prior_stage, days_in_stage, stage_start_date,
       action, structure_support, invalid_level, close
FROM cpa_stage_daily
WHERE stock_code = ? AND date <= ?
ORDER BY date DESC LIMIT 1;
```

**报告里必须原样引用引擎的阶段名与天数，并在括号里标注「引擎判定，非人工估计」。**

#### 九阶段与动作（引擎权威定义）

| stage | 名称 | action |
| :--- | :--- | :--- |
| ⓪ | Pending Breakout 待确认突破 | 待确认（次根 K 线收盘定夺） |
| ① | Reversal Extension 反转尝试 | 观察 |
| ② | Wedge Pop 突破 | **买入信号** |
| ③ | EMA Crossback 回踩 | 观察 |
| ④ | Base 'n Break 基部突破 | 观察 |
| ⑤ | Exhaustion Extension 衰竭延伸 | **持有，不减仓** |
| ⑥ | Wedge Drop 破位下坠 | **离场信号** |
| ⑦ | EMA Crossback Downside 下行回踩 | 观察 |
| ⑧ | Base 'n Break Downside 下行平台破位 | 观察 |

**注意 ② 与 ④ 的区别是位置性的，不是形态性的**：② = 突破后确立上升（前环境 ≠ UP），④ = 延续性突破。二者都是买点候选，但 ② 更强。

#### **必须读全部状态字段——只报阶段标号会误导（踩过坑）**

**阶段标号只是一个粗标签，同一个标号内部可能方向相反。** 实测万华 600309（2026-10-28）：

```json
{"stage":"⑥", "six_dir":"rebound", "close":70.46,
 "ema10":68.226, "ema20":68.667, "invalid_level":68.67,
 "structure_support":64.92, "action":"观察", "days_in_stage":2}
```

**若只报「⑥ 破位下坠」——标号对，但状态说反了。**
⑥ 的内部方向 `six_dir = rebound`（反弹），价格已站上 EMA10/EMA20，
失效位 68.67 未跌破。真实状态是「⑥ 内反弹、向 ② 演进的待明阶段」。

**Oliver Kell 必须原样引用以下五项，缺一项即不合格：**

| 字段 | 来源 | 含义 |
| :--- | :--- | :--- |
| `stage` + 名称 | `stage` | ⓪~⑧ 标号 |
| **`six_dir`** | `metrics_json` | **⑥ 内部方向：`rebound` / `fall`**。⑥ 不等于一定在下坠 |
| **`invalid_level`** | 表字段 | **失效价**。⑥ 时通常 = EMA20，跌破才确认 |
| `structure_support` | 表字段 | 结构支撑位 |
| **最近一次转换的确认状态** | `cpa_stage_transitions.invalidated`（0/1）<br>或 API 派生的 `inv_state` | **表里只有 `invalidated`（0=仍有效／1=已推翻）与 `invalidated_date`，没有 `inv_state` 字段** |

**尤其注意转换的确认状态：** ⑦→⑥ 若尚未确认，说明 ⑥ 还没被坐实，
**此时报「已破位」是错的，应报「破位待确认」。**

> **数据位置订正（2026-10-29）**：`cpa_stage_transitions` 表**没有** `inv_state` 字段。
> `inv_state`（`valid` / `pending` / `invalidated`）是 `GET /api/cpa/stock?code=` 返回时**派生的**，
> 查表拿不到——必须走 API，或自行由 `invalidated` + `invalidated_date` 推断：
> `invalidated=1` → invalidated；`invalidated=0` 且近期无 `invalidated_date` → valid/pending。

**接口 `/api/cpa/stock?code=<CODE>` 已返回 `daily[]`（含 ema10/ema20/six_dir/invalid_level）
与 `transitions[]`（含派生出的 `inv_state`），优先直接用该接口，避免漏字段。**

#### 铁律：买点与破位的不对称

> **买点需要次日确认**（突破日收盘站上关键位，次日收盘仍在关键位上方才算成立）；
> **破位不需要确认**（跌破即成立）。
> 这个不对称是刻意的——**错了要立刻走，对了可以等一下**。

#### 失效判定

引擎已给出 `invalid_level`（失效价）与 `structure_support`（结构支撑）。**报告必须直接引用这两个数值，不要自行推算**：

- 现价 < `invalid_level` → 立即离场
- 现价 < `structure_support` → 结构走坏，降级观察

#### Oliver Kell 必须输出的四项

1. **引擎阶段**（⓪~⑧ + 名称 + 已持续天数 + action）
2. **⑥ 时的内部方向**（`six_dir` = rebound / fall；非 ⑥ 可略）
3. **支撑与失效位**（`structure_support` / `invalid_level` 原值）
4. **转换确认状态**（最近一次 `inv_state` = valid / pending / invalidated）
5. **风险收益比** = (到最近压力位涨幅) ÷ (到 `invalid_level` 跌幅)。**< 2 时投「等」或「回避」。**
6. **周线共振**（`cpa_stage_stock_weekly` 的阶段是否与日线一致；不一致要说明）

#### 入条件里的 CPA 规则

评估脚本支持 `cpa_stage` 规则：

```json
{"type": "cpa_stage", "in": ["2", "4"]}
{"type": "cpa_stage", "not_in": ["6", "8"]}
```

**典型买点条件：`{"type":"cpa_stage","in":["2"]}`——只在引擎给出 ② 买入信号时才提醒。**

### 步骤 9 · 九大师单向投票（奇数票制）
每人在一行内给：**票（买/等/回避）+ 一句理由**。禁止并列表述。
- 欧奈尔（技术买点/机构吸筹/CANSLIM）：看买点质量、相对强度、量价、机构行为
- 威科夫（市场结构）：判断吸筹/派发/拉升/下跌阶段 + 量价验证
- 利弗莫尔（趋势/关键点）：趋势是否成立、关键点突破/失效
- 段永平（商业模式/本分）：生意看得懂吗、管理层本分吗、能力圈
- 巴菲特（护城河/估值/资本配置）：护城河宽窄、估值安全边际、资本配置理性
- 芒格（逆向/风险/心智）：最大的风险是什么、我可能错在哪、有什么致命缺陷
- 索罗斯（反身性/周期）：趋势自我强化的阶段（早期/中段/后段）、共识叙事是否已被价格透支、反身性转向风险
- **Oliver Kell（CPA 价格行为循环）**：**只看价格行为，不看基本面**。九阶段定位（反转延伸/楔形突破/EMA回踩/基部突破/衰竭延伸/破位/基部构筑/上升趋势回踩/派发）；必须回答：现价处于哪一阶段、EMA10 与 EMA20 关系、量能是否配合、风险收益比数值、买点是否需要次日确认
- **Michael Mauboussin（预期投资 / 价格反推）**：**只反推价格隐含了什么，不判断公司好坏**。必答：当前价格隐含的增长率/利润率是多少？该隐含值 vs 基本面趋势是偏高还是偏低？ROIC 是否高于 WACC（增长在创造还是毁灭价值）？市场预期正在往哪个方向修正

### 步骤 9.5 · 入条件清单（九位必答，禁止只投否定票）

**问题背景**：九位大师很容易齐声说「观望、PE 偏高、等回调」——
**这种报告对读者毫无用处**。读者要的不是「现在不行」，而是**「怎样才行、差多少」**。

**铁律：每一位大师在给出票之后，必须再用一组可量化的数值回答：**

> **「满足什么条件，我会改投『买』？」**

**禁止句式**：「等估值合理」「等回调到位」「等基本面改善」——这些无法执行。
**必须给数字、给区间、给可观测的触发信号。**

#### 各大师的必答条件（按其自身视角，不许串味）

| 大师 | 必须给出的量化条件（任选 3~5 条，须带具体数值） |
| :--- | :--- |
| **欧奈尔** | CANSLIM 总分 ≥ ? ／ C 分 ≥ ? ／ RPS250 ≥ ? ／ 是否出现基部突破且量 ≥ 20日均量 ×? ／ 距 52 周高点 ≤ ?% |
| **威科夫** | 吸筹阶段完成标志（Spring 或 Test 是否出现、量能萎缩至 20日均量 ?%）／ 是否突破 creek 且回踩不破 ／ 放量阳线数量 ≥ ? 根 |
| **利弗莫尔** | 关键点价位 = ? ／ 需连续站稳该价位 ? 日 ／ 趋势线（或 MA?）站上 ／ 成交量放大至 ? 倍 |
| **段永平** | 生意看得懂的判断（一句话）／ 愿意支付的价格区间 = ? 元（对应 PE ?~? 倍）／ 需要看到什么经营数据转向 |
| **巴菲特** | DCF 折价 ≥ ?%（现价需低于内在价值多少）／ ROE 连续 ? 年 ≥ ?% ／ 自由现金流 ≥ ? 亿 ／ 负债率 ≤ ?% |
| **芒格** | 必须先消除的风险清单（现金含量 ≥ ?x、FCF 是否转正、有无重大诉讼/关联交易）／ 最大风险由什么数据证伪 |
| **索罗斯** | 反身性处于哪个阶段（早期/中段/后段）／ 需看到什么叙事转折 ／ 共识是否已被价格透支（用 ? 指标衡量） |
| **Oliver Kell** | 必须进入哪个 CPA 阶段（基部突破/EMA回踩/上升趋势回踩）／ 需满足 EMA10 与 EMA20 的什么关系 ／ **风险收益比 ≥ ?**（到压力位涨幅 ÷ 到失效位跌幅）／ 失效位 = ? 元 |
| **Mauboussin** | 反推隐含 g 需降至 ≤ ?%（对应 PE ≤ ?）／ 或自身近 3 年 CAGR 需修复至 ≥ ?% ／ ROIC 需 ≥ WACC + ?pp |

#### 输出格式（硬性）

**表一：九位大师的入条件清单**

| 大师 | 当前票 | 入条件（量化） | 当前值 | 达成度 |
| :--- | :--- | :--- | :--- | :--- |
| 欧奈尔 | 回避 | CANSLIM ≥ 60、RPS250 ≥ 85、基部突破量 ≥1.5x | 27.6、79、未突破 | 0/3 |
| … | … | … | … | … |

**「达成度」写成 `已达成项数 / 条件总数`，让读者一眼看出还差多远。**

**表二：合并后的「综合入条件」（主持人汇总）**

把九人的条件按「最常被提及」排序，合并出 **3~5 条决定性的门槛**，例如：

| 优先级 | 条件 | 当前 | 缺口 |
| :--- | :--- | :--- | :--- |
| **P0（必须）** | 风险收益比 ≥ 2 | 1.3 | 需价跌至 62 或压力位升至 78 |
| **P1** | CANSLIM ≥ 60 | 27.6 | 需 C+N+S 合计再增 30 分 |
| **P2** | 隐含 g ≤ 0% | +2.2% | 需 PE 降至 10 以下 |

**P0 未满足时，无论其他条件多好都不应买入**——这是主持人的否决线。

#### 情景化：「如果……那么……」

**必须再给 2~3 条「如果 A 发生，我就改投买」的完整情景**，每条都要能落到价位与时间：

- 「若股价回落到 **62 元以下**（对应 PE 11.3、风险收益比 2.4）**且** CANSLIM 升至 50+，则 9 人中至少 5 人会转投买」
- 「若 Q4 毛利率回升至 **18% 以上**且 FCF 转正，则价值派 3 票可转买」
- 「若放量突破 **72.62（MA60）**且量能 ≥1.5x，则技术派 4 票可转买」

**这一节是整份报告里读者最该带走的内容——因为它是可执行的、有明确触发点的。**

### 步骤 9.6 · 把入条件写入自选提醒系统（报告交付的最后一步）

**报告不是终点。** 入条件必须写进系统，才能每天自动对照自选池、在驾驶舱提醒。

**每份报告交付时必须附一条可直接执行的写入命令：**

```bash
python scripts/eval_entry_conditions.py --code <CODE> --name "<名称>" \
  --summary "<一句话条件总结>" \
  --source "<YYYY-MM-DD 个股体检报告>" \
  --add '[{"type":"price_above_ma","n":60},
          {"type":"vol_ratio","op":">=","v":1.5},
          {"type":"canslim","op":">=","v":65}]'
```

**写入后立即评估一次，输出当前达成度。**

#### 规则 DSL（可用类型）

| type | 参数 | 含义 |
| :--- | :--- | :--- |
| `price_above_ma` | `n` | 收盘价 > MA(n)，如站上 MA60 |
| `price_below_ma` | `n` | 收盘价 < MA(n)，如回踩 MA20 |
| `vol_ratio` | `op`, `v` | 5日均量/20日均量，如 `>= 1.5` 放量 |
| `canslim` | `op`, `v` | CANSLIM 总分，如 `>= 65` |
| `pe_pct` | `op`, `v` | PE 三年分位（%），如 `<= 20` |
| `rsi` | `period`, `op`, `v` | RSI，如 `rsi6 <= 30` |
| `dist_high` | `op`, `v` | 距 250 日高点（%，负值），如 `>= -10` |
| `pos_250` | `op`, `v` | 250 日区间位置（%），如 `<= 30` |
| `turnover` | `op`, `v` | 当日成交额（亿），如 `<= 6` |

**取条件的纪律：**

1. **只写 P0/P1 级条件**，不要把所有建议都塞进去——条件太多永远不触发，等于没写
2. **必须是本地库能算出来的量**（上表九类），写不出来的（如「等叙事转向」）不要写
3. **每条条件都要有明确阈值**，`{"type":"price_above_ma","n":60}` 而不是「站上均线」
4. **条件总数控制在 2~4 条**，且应当有先后（先价格位置、再量能、最后基本面确认）

#### 与驾驶舱的衔接

- 每日 `daily_update.py` 第 39 步自动评估（`39.自选股入条件评估`）
- 驾驶舱 `http://localhost:8772/cockpit/` 的「🔔 自选提醒」tab 读取
  `GET /api/cockpit/entry-alerts`
- **全部条件满足时 tab 计数变红、顶部出现提醒条**——此时应回看本报告的
  §入条件清单与情景，确认是否真的到了可执行的位置，而不是自动买入

#### 只对「在场」股票评估（省算力）

watchlist 表用 **
emoved_at IS NULL** 表示股票仍在自选池，移出的保留历史记录。
**移出自选池 = 不再关注 → 连评估都不做**（CANSLIM 评分要跑全部引擎，很贵）。

评估脚本已硬过滤：

`sql
SELECT c.* FROM stock_entry_conditions c
  JOIN watchlist w ON w.stock_code = c.stock_code
 WHERE c.enabled = 1 AND w.removed_at IS NULL
`

**两个必须遵守的点：**

1. **查 watchlist 一律带 
emoved_at IS NULL**。只看行数会误判——
   实测表里 37 行，但在场只有 8 只，其余 29 只是历史移除记录。
2. **移出的股票条件保留不删**（enabled=0）。重新加回自选池时
   _sync_enabled() 会自动恢复启用，不需要重写条件。

#### 数据表

| 表 | 用途 |
| :--- | :--- |
| `stock_entry_conditions` | 存条件（`rules` 为 JSON 数组） |
| `stock_entry_alerts` | 每日评估结果，主键 `(stock_code, date)`，幂等覆盖 |

### 步骤 9.7 · 各大师独有的入场条件（已落地的量化口径）

**原则：九位各有自己的方法论，入场条件必须反映各自的方法，不许都套同一组均线/量能。**

**结论会互相矛盾，这是正常的、也是要的**——欧奈尔买新高、威科夫买底部、利弗莫尔等关键点，
同一只股票他们给出相反意见完全合理。**不要为了「统一」而抹平分歧。**

---

#### 欧奈尔（CANSLIM + 口袋支点 + 强度）

| 条件 | 数据源 | 阈值 |
| :--- | :--- | :--- |
| CANSLIM 总分 | `canslim_score` | **≥ 65** |
| 口袋支点 | `pocket_pivot_daily` | **近 10 日内出现** |
| 突破放量 | `daily_kline` 量比（5日/20日） | **≥ 1.5** |
| 距 52 周高 | 现价 / 250日最高收盘 | **≥ −15%**（即距高点不超过 15%） |

**四条全满足才算欧奈尔的买点。**

> **杯柄形态（`cup_handle_v2_daily`）已不纳入条件。**
> 原因：实测该形态在当前市场极少出现（全自选池 0 例），
> 且欧奈尔的四种基部（杯柄/平底/碟形/双重底）本质等价，不必绑定其中一种。
> 口袋支点已能代表「基部突破」这一类。
> 若某股恰好出现杯柄，可作为加分项在报告中提及，但不作为门槛。

#### 威科夫（Spring → Test → SOS 三段式）

**威科夫的核心不是指标，是「谁在吸筹、谁在派发」。个股没有现成引擎
（`distribution_day.py` 是指数抛盘日引擎），须按量价现算。**

**三段式买点的顺序是强制的：先 Spring，再 Test，最后 SOS。**

| 阶段 | 定义 | 量化判定 |
| :--- | :--- | :--- |
| **前提：箱体** | 横盘窄幅，主力在此收集筹码 | **近 60 日振幅 ≤ 35%**。振幅过宽说明是下跌趋势而非箱体，此时出现的「破位收回」多为下跌中继反弹，**不算 Spring** |
| **① Spring** | 跌破箱体下沿后快速收回（假破位，吓出散户） | 近 30 日内某日收盘 < 此前 60 日最低收盘 × 0.99，且 **5 日内**收回该位之上 |
| **② Test** | Spring 后的缩量回踩，确认卖压枯竭 | Spring 之后 **5~15 日**内出现回踩日，满足：<br>· 当日量 **≤ 20日均量 × 0.70**<br>· 最低价 **≥ Spring 低点 × 0.98**（不实质破位） |
| **③ SOS** | Sign of Strength，放量突破箱体上沿 | 近 5 日内收盘 > 60 日箱顶 × 1.005，且当日量 **> 20日均量 × 1.5** |

**投票规则：**

| 状态 | 票 |
| :--- | :--- |
| SOS 已现 | **买**（拉升启动） |
| Spring + Test 双确认 | **买**（吸筹完成，等 SOS 加仓） |
| 只有 Spring，无 Test | 等（未确认，可能是假 Spring） |
| 横盘（振幅≤25%）+ 量能萎缩（≤0.9）+ 低位（位置≤45%），但无 Spring | 等（吸筹中，尚未触发） |
| 位置 ≤20% 且量能未萎缩 | **回避**（下跌未止，不是吸筹） |
| 箱体振幅 >35% 且无有效 Spring | 等或回避（无箱体，无从判断吸筹派发） |

**辅助判据（写进报告，不单独定票）：**

- **吸筹日 / 抛盘日**：近 25 个交易日内，放量（>前 5 日均量 ×1.1）且涨跌幅 >+0.2% 为吸筹日；放量且 <-0.2% 为抛盘日。**吸筹日显著多于抛盘日 = 偏多**。
- **量能萎缩比**：5日均量 / 20日均量。**≤0.8 = 卖压枯竭**。

**报告必须输出**：箱体上下沿、Spring 日期与低点、Test 日期与量比、SOS 日期、
吸筹日/抛盘日计数、当前所处的三段式位置。

> **阈值状态（诚实标注）**：箱体 ≤35%、Test 量 ≤0.70、SOS 量 >1.5x 均为经验值，
> **未做历史回测校准**。若要作为主要决策依据，需先验证「满足三段式后未来 20/60 日收益
> 是否显著高于不满足」。当前定位为「辅助判断 + 报告叙述依据」。

#### 巴菲特（护城河 + 安全边际 + 现金质量）

**巴菲特只问四件事：生意好不好、价格便不便宜、赚的是不是真钱、杠杆高不高。
四项全过才投「买」——他不接受「三项不错所以可以买」。**

| 条件 | 量化 | 数据源 | 阈值 |
| :--- | :--- | :--- | :--- |
| **① ROE 持续性** | 近 **5 年** ROE | `stock_financials_annual.roe` | **均值 ≥ 15% 且最低年份 ≥ 12%** |
| **② 安全边际** | DCF 目标价 / 现价 − 1 | `/api/stock-analysis` 的 `dcf.target_price` | **≥ +30%** |
| **③ 现金质量** | 近 **3 年**自由现金流 | `stock_financials_annual.free_cash_flow` | **每年 > 0** |
| **④ 杠杆** | 资产负债率 | `stock_financials_annual.asset_liability_ratio` | **≤ 60%** |

> **数据口径（2026-10-29 补充）**：以上四项**主判据用年度数据**——
> 巴菲特看的是「十年后还能不能保持」，年度口径才对。
> 但**必须加一条季度预警**：最近的季度 FCF、扣非占比若连续两季恶化，
> 即使年度数据尚可，也应在报告中标「恶化正在发生」。
> **年度数据滞后，季度才是警报。**
> **TTM 口径（2026-10-29 订正，必读）**
>
> `stock_financials_quarterly.free_cash_flow` 存的是**累积值**（理杏仁 `q.m.fcf.t`，YTD），
> **不是单季值**。Q4 累积 = 全年，与年报同值——这是正确的，不是数据错误。
>
> **TTM 的正确算法：**
> ```
> TTM = 本期累积 + (上年全年 − 上年同期累积)
>     = 上年全年 + 同比增量
> ```
>
> **两个必须避免的错法（本人都踩过）：**
> 1. ❌ 把「本期累积 − 上年同期累积」当成 TTM —— 那是**同比增量**，不是 TTM
> 2. ❌ 把四个累积值相加 —— 累积值相加毫无意义
>
> **自检**：算完 TTM 后，用「上年全年 + 同比增量」交叉验证，
> 且 TTM 相对上年全年的变化方向必须与同比增量的符号一致。
> **若出现「同比增量 +55 亿」却得出「变化 −165 亿」，说明减法方向用反了。**
>
> **为什么必须用 TTM**：年度数据滞后最多一年。实测万华化学
> 年报 FCF 近 3 年为 +29/−53/−163 亿（判为两年为负），
> 但 TTM（截至 2026Q3）= **+163.5 亿**，是近三年最好水平——
> **用年报会得出与事实相反的结论。**

> **巴菲特 FCF 条件的最终口径**：
> **近 3 年年度 FCF + TTM FCF 双轨**。若年度为负但 TTM 已转正且趋势向上，
> 应标「**现金流修复中**」而不是直接判 ❌——但要注明「修复可持续性未验证」。

**门槛是「均值 ≥15% 且最低年份 ≥12%」，不是「每年都必须 ≥15%」，也不是「现在高就行」。**

> **为什么从「每年 ≥15%」放宽（2026-10-30 用户决定）**
>
> 原口径下，六只已分析标的中只有卫星化学通过，连万华（12.6/14.9/20.8/22.3/40.6）都被排除。
> **A 股制造业中能连续 5 年每年 ROE ≥15% 的公司确实稀少，原门槛使巴菲特几乎不投票。**
> 新口径保留「均值达标 + 底部不失守」的双重约束，容忍单年周期波动，
> 同时仍能排除真正弱的公司（博众均值仅 10.2%）。

**实测对照：**

| 标的 | ROE 五年序列 | 均值 | 最低 | 旧口径 | 新口径 |
| :--- | :--- | ---: | ---: | :---: | :---: |
| 卫星化学 | 16.6/21.7/20.1/15.2/36.4 | 22.0 | 15.2 | ✅ | ✅ |
| 万华化学 | 12.6/14.9/20.8/22.3/40.6 | 22.2 | 12.6 | ❌ | **✅** |
| 中远海控 | 12.4/21.0/11.4/60.7/80.6 | 37.2 | 11.4 | ❌ | ❌（最低差 0.6） |
| 杰克科技 | 17.4/18.0/12.2/12.9/15.0 | 15.1 | 12.2 | ❌ | **✅** |
| 博众精工 | 12.6/9.0/9.7/10.6/9.2 | 10.2 | 9.0 | ❌ | ❌ |

> **仍要保留的判断**：巴菲特买的是「十年后还能赚这么多」，**ROE 的趋势比绝对值更重要**。
> 药明康德 27.8 / 16.7 / 18.9 / 20.8 / 14.4 / 11.9 呈单调下滑，
> 即便均值达标，也应在报告中标注「趋势恶化」。

**投票规则：**

| 达成 | 票 |
| :--- | :--- |
| 4/4 | **买** |
| 3/4 | 等（差哪一条要写明） |
| 2/4 | 等 |
| ≤1/4 | **回避** |

**特殊情形：DCF 目标价为负 → 直接回避，不看其他三项。**

> 实测：隆基绿能 DCF = **−5.13 元**。按当前现金流，内在价值为负，
> 这是模型给出的明确信号，无需再讨论 ROE 或负债率。

**报告必须输出**：ROE 近 6 年序列（标注哪年跌破 15%）、FCF 近 6 年序列（亿元）、
DCF 目标价与折价率、负债率，以及**差在哪一条**。

> **阈值状态**：15% / 30% / 60% 是巴菲特公开表述的传统标准，非本项目调参结果。
> DCF 结果对 WACC 与终值倍数高度敏感（同一只股票在 EV/EBITDA 4x~12x 下
> 目标价可差 4 倍），**因此 DCF 折价只作参考，报告须同时给出敏感性区间**。

#### 芒格（Invert——先问「会怎么亏钱」）

**芒格不问「这股票能涨多少」，而是「这笔投资会怎么弄死我」。**
**他的投票是排雷式的：雷点越少越好，与其他人越算越优的方向相反。**

| 排除项 | 量化 | 数据源 | 雷线 |
| :--- | :--- | :--- | :--- |
| **① 利润没变成钱** | 现金含量 = 近 3 年累计 FCF ÷ 近 3 年累计净利 | `stock_financials_annual` | **< 0.5x** |
| **② 利润靠非经常损益** | 扣非净利 ÷ 净利（最近一期有值） | `net_profit_adj / net_profit` | **< 70%** |
| **③ 筹码急剧分散** | 股东户数近 6 期变化 | `shareholders_num_daily.total` | **> +30%** |
| **④ 杠杆过高** | 资产负债率 | `asset_liability_ratio` | **> 70%** |
| **⑤ 近 3 年累计亏损** | 3 年累计净利 | `net_profit` | **≤ 0** |

> **数据口径（2026-10-29 补充）**：排雷主判据用年度数据，但**必须加季度预警**——
> 芒格的排雷本质是「避免永久性损失」，**最近季度现金含量或扣非占比突然恶化，
> 正是最早的警报**。年度数据要等一年，季度只要三个月。
> **芒格「现金含量」的最终口径（重要）**：
> **主用 TTM 口径**：现金含量 = TTM FCF ÷ TTM 净利；**年度累计值作参考**。
>
> 理由：排雷要抓「现在是否在失血」，TTM 才反映当下。
> 实测万华化学：年度累计口径算出 **−0.44x**（命中雷点），
> TTM 口径算出 **+1.08x**（完全通过）——**同一家公司，两个口径两个结论。**
> 年度口径的 −0.44x 反映的是 2023-2025 的历史，而 2026 年现金流已实质转正。

**判读：雷点 0 个 → 买；1 个 → 等；≥2 个 → 回避。**

#### 两个必须注意的技术细节（踩过坑）

**① 累计净利 ≤0 时，「现金含量」比率无意义**

分母为负会算出**假正值**。实测隆基绿能近 3 年累计净利为负、累计 FCF 为正，
直接相除得 **3.43x**，看起来现金质量极好——**这是错的**。
正确做法：先判「近 3 年累计亏损」，命中直接记一个雷点，**不计算现金含量**。

**② 股东户数表是 `shareholders_num_daily`，不是 `shareholders_num`**

`shareholders_num` 只有 4 行（基本是空表），真实数据在 `shareholders_num_daily`（20 万+行）。
字段为 `total`（户数）、`change_rate`、`price_change`。

#### 芒格与其他人的天然分歧（写报告时要呈现）

| 情形 | 巴菲特 | 芒格 |
| :--- | :--- | :--- |
| 好生意 + 筹码分散 | 买（生意好就行） | **等或回避**（聪明钱在卖给散户） |
| 普通生意 + 现金质量极佳 | 未必买（ROE 不够） | **买**（不出事最重要） |

**实测例**：卫星化学巴菲特 4/4 买，芒格因股东户数 +53.9% 只给「等」；
潍柴动力巴菲特 1/4（ROE 10.8% 不达标），芒格 0 雷点给「买」。

**报告必须把这种分歧写明，不要调和成一个结论。**

> **阈值状态**：0.5x / 70% / 30% / 70% 为经验值，未做回测校准。
> 芒格的排除项本质是「避免永久性资本损失」，宁可错过也不踩雷，
> **因此他的「回避」比其他人的「回避」更该被重视**。

#### Mauboussin（预期投资——反推价格已经假设了什么）

**他不问「这公司好不好」，问「当前价格隐含了什么假设，这些假设合理吗」。**
**这是唯一一位「从价格出发」而不是「从公司出发」的大师。**

##### ① 反推隐含增长率

```
隐含增长率 g = WACC − 1/PE        （稳定增长模型 PE = 1/(WACC−g) 反解）
```

**WACC 取 10%**（无风险 1.7% + 股权风险溢价 5% + 周期/小盘溢价约 3%）。

##### ② 用「扣非 + 双轨」估可持续增速

| 轨 | 算法 | 数据源 |
| :--- | :--- | :--- |
| **年度轨** | 扣非净利 3 年 CAGR | `stock_financials_annual.net_profit_adj` |
| **季度轨** | **TTM 扣非 YoY** = 近 4 季扣非合计 ÷ 前 4 季合计 − 1 | `stock_financials_quarterly.net_profit_adj_single` |

**两条铁律：**

1. **必须用扣非（`net_profit_adj`），不用净利。**
   实测药明康德 2025 年净利 192 亿、扣非仅 132 亿——60 亿是一次性收益，
   用净利算出的 3 年 CAGR **29.5%** 是虚高，用扣非算只有 **17.0%**。
2. **季度轨用 TTM，不用「近 4 季 YoY 均值」。**
   单季 YoY 波动极大（卫星化学近 4 季为 121%/240%/15%/480%），
   均值会被极端值带偏；TTM 口径把 4 个季度加总，稳健得多。

##### ③ 判定：背离时不许自动定票

```
差 = 可持续增速 − 隐含 g
差 ≥ +5pp → 买（价格隐含的预期偏低）
差 ≤ −5pp → 回避（预期偏高）
−5 < 差 < +5 → 等
```

**但当「年度轨」与「季度轨」方向相反、且背离 > 30pp 时：**

> **不许取较低者或较高者自动定票。必须标记「⚠ 拐点」，并给出两种情景。**

**实测例（万华化学 2026-10-29）：**

| 情景 | 增速 | 隐含 g | 差 | 对应结论 |
| :--- | :--- | :--- | :--- | :--- |
| 按 TTM | +59.3% | 1.4% | **+57.9pp** | 预期严重偏低 → 买 |
| 按 3 年 CAGR | −8.4% | 1.4% | **−9.8pp** | 预期偏高 → 回避 |

**报告必须并列两个结论，并写明「分歧源于『近期复苏能否持续』这一未知」，而不是替市场做判断。**

##### ④ ROIC vs WACC（增长是在创造还是毁灭价值）

```
ROIC = 净利 × (1 − 25%) ÷ (有息负债 + 股东权益)
价值创造 = ROIC − WACC
```

- **ROIC > WACC**：增长创造价值，增速越快越该给溢价
- **ROIC < WACC**：**增长毁灭价值**，增速越快反而越该压低估值

> **ROE 会骗人，ROIC 不会。** ROE 可被杠杆放大；ROIC 剔除资本结构影响，
> 反映真实资本效率。实测卫星化学 ROE 16.6%（巴菲特认可）但 ROIC 仅 6.9%，
> **低于 WACC 10%——按 Mauboussin 框架，它的增长在毁灭价值。**
> 这正是他与巴菲特对同一只股票给出相反结论的根源。

##### ⑤ 与巴菲特的分工（报告要把分歧写明）

| | 巴菲特 | Mauboussin |
| :--- | :--- | :--- |
| 出发点 | 公司值多少钱（DCF） | 价格假设了什么（反推） |
| 关键指标 | ROE、FCF | **ROIC、隐含 g** |
| 结论差异根源 | 看盈利能力 | 看**资本效率与预期差** |

**实测：卫星化学巴菲特 4/4 买（DCF 折价 65.6%），Mauboussin 也算「买」（预期差 +29.8pp），
但理由完全不同——前者认为它便宜，后者认为市场低估了它的增长。**

##### 阈值与局限（诚实标注）

- WACC 固定 10% 是简化；不同行业应有不同的资本成本
- ROIC 为粗算（分子用净利而非 NOPAT 的严格口径，分母未剔超额现金），误差可能 ±2pp
- **PE 为负或亏损的股票无法反推隐含 g**（实测隆基绿能近两年亏损，本项直接不适用）
- 「可持续增速」本质上是对未来的主观判断，双轨与拐点标注只是把这个判断显性化

#### 索罗斯（反身性——趋势在哪个阶段，共识是否已被价格透支）

**他不问「贵不贵」，问三件事：趋势的自我强化走到哪一步、共识叙事是否已被价格透支、系统性环境是否允许冒险。**
**他是九位里唯一「先看系统、再看个股」的人。**

##### ① 系统性环境：`market_health`（项目自建模型，非索罗斯原教旨）

**数据源：`GET /api/market-health`，实现见 `src/scanners/market_health.py`。**

| 总分 | 等级 | 建议仓位 |
| :--- | :--- | :--- |
| ≥80 | A | 70% |

| ≥35 | D | 20% |

**总分由 8 项加权：`ma50_above`（MA50 上方个股占比）、`ad_ratio`（涨跌比）、

##### ② 拥挤度（资金是涌入还是撤离）——必须多窗口，不能只看短窗口

**踩过的坑**：只用「近 250 日换手率分位」会严重误判。实测：

| 股票 | 250日分位 | 1250日分位 | 只看 250 日的错误结论 |
| :--- | :--- | :--- | :--- |
| 卫星化学 | **1%** | 31% | 「极度冷清」 |
| **万华化学** | **14%** | **62%** | 「极冷」← **完全相反** |

**原因：换手率中枢本身在漂移（卫星 750 日中位 0.913% vs 250 日中位 1.471%），
短窗口比较会把「正常」误判成「萎缩」。**

**正确算法（三项组合）：**

| `turnover_ratio` | 判定 | 含义 |
| :--- | :--- | :--- |
| ≥ 1.5 | **过热** | 资金涌入，共识可能已形成 |
| 1.2 ~ 1.5 | 偏热 | — |
| 0.8 ~ 1.2 | **正常** | 与自身长期中枢一致 |

#### 利弗莫尔（关键点法）

**他的体系只有三条：只在关键点买、关键点必须被确认、永不逆势加仓。**

| 条件 | 定义 | 阈值 |
| :--- | :--- | :--- |
| **关键点（pivot）** | **近 250 日最高收盘，排除最近 5 日**（避免用自己当关键点） | — |
| 突破 | 现价 > 关键点 | **> pivot × 1.005** |
| 接近（可埋伏） | 距关键点 | **≥ −3%** |
| 量能确认 | 量比（5日/20日） | **≥ 1.3** |
| 站稳 | 连续收盘在 `pivot × 1.005` 上方的天数 | **≥ 3 日** |

**判定：**

| 状态 | 条件 | 结论 |
| :--- | :--- | :--- |
| **买点成立** | 突破 + 量能 ≥1.3 + 站稳 ≥3 日 | 投「买」 |
| 突破缺量 | 突破但量能不足 | 投「等」——假突破概率高 |
| 逼近关键点 | 距 pivot ≥ −3% 但未突破 | 投「等」——入观察名单 |
| 远离 | 距 pivot < −3% | 投「回避」——不在他的射程内 |

> **关键点为什么只用前高，不用「基部上沿」：**
> 基部（base）的边界定义主观，不同人划出的上沿不一样，无法量化。
> 前高是唯一无争议的关键点。用户在 2026-10-29 明确要求以此为准。

**「永不逆势加仓」的落地：** 若现价低于 `pivot`，利弗莫尔**不允许任何形式的加仓**，
即使其他八位投买。他的加仓点是「突破后回调不破 pivot、再创新高」。

##### 五个固定选择（本项目已验证）

**① 默认浅色模式**

`<html lang="zh-CN" data-theme="light">`。hanako-glass 默认深色，但投研报告在浅色下可读性更好，
**必须在 `<html>` 上写死 `data-theme="light"`**，同时保留 `◐` 切换按钮与 `localStorage` 记忆。

**② 标题用 Noto Serif SC 900**

`Instrument Serif` **不含中文字形**，也没有 700 字重。中文标题必须回退到真有字重的衬线字体：

```
https://fonts.googleapis.com/css2?family=Instrument+Serif:ital@0;1&family=Inter:wght@300;400;500;600&family=JetBrains+Mono:wght@400;500&family=Noto+Serif+SC:wght@400;700;900&display=swap
```

```css
:root{ --font-display: 'Instrument Serif', 'Noto Serif SC', Georgia, 'Songti SC', serif; }
h1,h2,h3,h4,.nav-brand,.master-top .nm{font-weight:900 !important;letter-spacing:.005em}
```

**必须验证字体真的下载了**：
`[...document.fonts].some(f => f.family.includes('Noto Serif SC') && f.status === 'loaded')`。
若标题的 computed `fontFamily` 里没有 Noto，说明 `:root` 覆盖没生效——
**浏览器只有在有元素用到该字体时才会下载它**。

> **踩过的坑**：第一次只改了 `font-weight` 没改字体栈，结果 Noto 从未被请求，
> 中文仍走系统宋体 + 合成粗体，看不出效果。

**③ 表格首列左对齐（共享 CSS 的默认值不适用）**

hanako-glass 的 `.data-table td / th` 默认 **`text-align:center`**（面向数据仪表盘）。
报告是长文档，首列必须有左阅读轴，**每个报告都要加这段覆盖**：

```css
.data-table th:first-child,.data-table td:first-child{text-align:left;padding-left:16px}
.data-table th:last-child,.data-table td:last-child{padding-right:16px}
.data-table td:not(.num):not(.mono){text-align:left}
.data-table td.mono{text-align:left}
/* .num 专用于数值列（右对齐 + 等宽 tabular-nums）；.mono 用于等宽但左对齐的内容列 */
.data-table td.num,.data-table th.num{font-family:var(--font-mono);text-align:right;font-variant-numeric:tabular-nums}
.mono{font-family:var(--font-mono);font-variant-numeric:tabular-nums}
`

**③-b 末列（判定/结果列）必须居中，并与数值列拉开间距**

数值列右对齐、判定列左对齐时，两列会连成一片，判定文字看起来像数值的后缀。
**居中是最省事的分隔手段**——两侧对称留白，天然形成「白色走廊」：

`css
.data-table th:last-child,.data-table td:last-child{padding-right:16px;padding-left:28px}
.data-table td:last-child:not(.num):not(.mono),
.data-table th:last-child{text-align:center}
`

**③-c 两列表格必须加 .wide（末列居中会误伤）**

「项目 / 内容」「问题 / 回答」这类**两列说明表，内容列就是末列**，会被 ③-b 的居中规则接管，
导致整段落居中、无法阅读。**凡是两列表格，一律加 .wide 类：**

`css
.data-table.wide td:last-child{text-align:left!important}
`

| 表格类型 | 是否加 .wide |
| :--- | :--- |
| 三列以上的评分表（条件/阈值/实际/结果） | 不加，末列居中 |
| **两列说明表（项目/内容、问题/回答）** | **必须加** |

> **踩过的坑**：终裁表与段永平的问答表都是两列，加了末列居中后整列文字居中，
> 视觉上像标题而不是内容。两列表格与多列表格的末列语义完全不同，
> **CSS 无法自动判断列数，必须由作者显式标注。**

> **踩过的坑**：只加 padding-left 仍显拥挤，因为左对齐时每行判定文字的起点
> 都紧贴数值列右边缘；**居中后左右同时留白，视觉分离才成立**。
``

> **踩过的坑**：给内容列误用 `.num` 会整列右贴；`.mono` 若不显式加 `text-align:left`，
> 会继承共享 CSS 的居中。

**④ 复用组件，不自造**

| 用途 | 类名 |
| :--- | :--- |
| 页面骨架 | `.app-container`（**外层只用一次，绝不嵌套**） |
| 顶栏 | `.top-nav` + `.nav-brand` + `.nav-links` + `.theme-toggle` |
| 卡片 | `.glass-card`（通用）/ `.chart-card`（图表）/ `.stat-card`（数字） |
| 表格 | `.table-shell` > `table.data-table` |
| 标签 | `.tag` / `.badge` |

**页面 `<style>` 只放报告特有样式，色值一律用 `var(--accent)` 等令牌，不写死。**

**⑤ 红涨绿跌——令牌名与 A 股惯例相反，必须自建语义类**

hanako-glass 的 `--rise` 是**绿** `#10b981`、`--fall` 是**红** `#ef4444`。
用户要求的是**红涨绿跌**（A 股惯例），**因此不能直接用 `--rise`/`--fall` 的名字**。

```css
.rise{color:var(--fall)}   /* 涨/买 → 红 */
.fall{color:var(--rise)}   /* 跌/卖 → 绿 */
```

> **这是最容易出错的一处**：按令牌名直觉用会全反。
> **报告正文统一用 `.rise`（语义=涨，色=红）与 `.fall`（语义=跌，色=绿），
> 语义与令牌名相反是刻意的。**

**⑤-b 红涨绿跌只适用于「价格方向」与「买卖票」，不适用于评分与比率**

`.rise` / `.fall` 的语义是**价格涨跌**。以下三类**必须用中性色**（不加这两个类）：

| 类别 | 例子 | 为什么不能用 |
| :--- | :--- | :--- |
| **评分** | CANSLIM 77.0、RPS 分位、估值分位 | 分数高不等于「涨」，77 分标红会让人误读为上涨 |
| **比率/倍数** | 负债率、换手率倍数、PE | 负债率高不是「涨」 |
| **估值差** | DCF 溢价 58% | 溢价是「价格高于价值」，与涨跌方向无关 |

**只有以下两类用 `.rise` / `.fall`：**

| 类别 | 例子 |
| :--- | :--- |
| **价格变动** | 现价相对均线 +1.6%、涨跌幅、距高点 −15.4% |
| **买卖票标** | 买入（红）、回避（绿） |

> **踩过的坑（2026-10-30）**：压力测试报告里把「CANSLIM 77.0」「DCF 溢价 58%」标成红/绿，
> 读者会误解为「上涨」或「下跌」。**评分与估值没有方向，颜色会制造假信号。**

### 3.2.1 分部业绩比较方法论（踩过的坑，必须按此做）

**反面教材（本发明过）：** 看到万华石化板块占收入 40%、毛利率仅 6.8%，
就下结论「增长质量低、靠低毛利业务撑收入」。**这个判断是错的。**

**正确做法：四步，缺一步就会得出反向结论。**

#### 第一步：认清披露节奏——分部数据只有半年报和年报

A 股季报**不披露分部构成**。营收构成 API 返回的期次实测为：

```
2026-06-29 (半年报)  2025-12-30 (年报)  2025-06-29 (半年报)  2024-12-30 (年报) …
```

**所以在写「Q3 某板块如何」之前先确认：Q3 有没有分部数据。没有就是没有，
不要从合计口径硬推分部结论，也不要说「数据拿不到」——是披露规则如此。**

**合计口径只能做交叉验证，不能替代分部：**
若某季合计毛利率低于上一个半年报的合计毛利率，说明该季整体毛利在回落，
此时「某板块该季改善更明显」这类推断需要证据，不能默认成立。

#### 第二步：必须同时看「毛利率水平」和「毛利率变化」

| 只看水平（错） | 加上变化（对） |
|---|---|
| 石化毛利率 6.8%，最低 → 「拖累项」 | 石化毛利率从 **−0.4% 到 +6.8%（+7.2pp）**，改善幅度全场最大 |

**周期股的板块毛利率长期在低位，恰恰说明它处在周期底部、弹性最大。
用「水平低」否定它，等于在最该关注的时候忽略它。**

#### 第三步：算「毛利额增量贡献」，这才是利润的真实来源

毛利率变化容易被小基数放大，必须换算成**绝对额增量**再排序：

```
毛利额 = 收入 × 毛利率
毛利额增量 = 本期毛利额 − 基期毛利额
贡献占比 = 该板块增量 ÷ 各板块增量之和
```

**万华实测（2025H1 → 2026H1）：**

| 板块 | 收入同比 | 毛利率变动 | 毛利额增量 | 贡献占比 |
|---|---|---|---|---|
| **石化** | +36.7% | **+7.2pp** | **+33.9 亿** | **44.2%** |
| 聚氨酯 | +21.9% | +1.4pp | +27.0 亿 | 35.3% |
| 精细化学品 | +44.3% | +6.7pp | +21.8 亿 | 28.4% |
| 其他 | +15.2% | −6.5pp | −6.0 亿 | −7.8% |
| 合计 | +29.9% | +3.1pp | **+76.7 亿** | 100% |

**结论完全反转：石化贡献了毛利额增量的 44.2%，是第一贡献者，不是拖累项。**

#### 第四步：一体化企业的分部利润率不能孤立解读

**垂直一体化公司的上游板块（石化、原料）常以内部转移价供应下游（聚氨酯），
利润在下游体现、成本在上游承担。**

因此：
- **上游板块毛利率低 ≠ 该板块无价值**，它的价值体现在「保证原料自给 + 降低整体成本」
- 这部分协同收益**无法从财报分部数据直接量化**，只能定性说明，且**必须标明「定性判断，不可量化」**
- 判断一体化企业，看的是**合计毛利率趋势**和**各环节是否都在改善**，而不是单看某一段

#### 输出要求（写进报告的业务画像一节）

必须给一张表，列为：
`板块 | 本期收入 | 基期收入 | 收入同比 | 基期毛利率 | 本期毛利率 | 毛利率变动 | 毛利额增量 | 贡献占比`

并配一句结论：**哪个板块是毛利额增量的第一贡献者，哪个是唯一恶化项。**

**禁止只列「收入占比 + 毛利率」两列就下判断。**

3. 价格：近期调价函、挂牌价

### 3.4 财报数据：先查库，不要假设缺失

**在说「财报没拉到」之前，必须先查：**

```sql
SELECT COUNT(*), MAX(report_date) FROM stock_financials_quarterly WHERE stock_code='<CODE>';
```

**已知**：万华 600309 有 55 期，最新到 2026-09-30（三季报已在库）。
`stock_financials_annual` 最新到 2025-12-31（年报口径本就滞后）。

**`collect_data.py` 的 §5/§K 段输出的季度数据就来自该表**——
如果 detail 输出里有数据，就说明库里有，不要在报告里写「未获取」。

对账口诀：**detail 输出有 = 库里有 = 报告可用**。

## 4. 输出长度纪律

- **报告末尾必须附一条可直接执行的 `eval_entry_conditions.py --add` 命令**（见 §步骤 9.6）；
- 终裁卡 + 投票表是硬结构；其余各步精炼，总报告 HTML 控制在 30-50KB
- 证据说话：每个判断带数据（具体数字或信号），禁止"基本面良好"式空话
- 诚实>好看：不确定处明说，与数据矛盾的直觉要标注"与数据不一致，存疑"
- <b>④财务评估与⑥择时是报告的"肉"，禁止简表</b>：
  - ④ 财务评估必含：4.1 季度盈利趋势近 8 季明细表（营收/净利/毛利率/同比，标注拐点季）→ 4.2 年度轨迹表（近 6-10 年 + TTM，标注周期位置与距前顶空间）→ 4.3 六卡实际输出（DCF 目标价+敏感性带 / comps 中位与可比明细 / model 预测标注"机械外推"局限 / quality 警示逐条 / cashflow 年度 OCF-FCF）——quality/cashflow 异常必须上升为风险提示
  - ⑥ 择时必含：6.1 均线系统全表（MA5~MA250 数值+现价相对位置+排列判断，MA120/250 压制要显式指出，禁笼统"多头"）→ 6.2 指标读数（MACD/KDJ/RSI6-12-24/BOLL）→ 6.3 量能与资金（量比/近10日涨跌量额/两融）→ 6.4 支撑压力（60/250日高低+斐波那契+BOLL+均线粘合位）→ 6.5 个股 vs 行业 RS 对比（差距显式）+ 缠论连续两日信号（翻转要警示）→ 6.6 近期 K 线/价格行为表 → 择时小结（关键位+两种情景路径）
  - <b>行业口径纪律（踩过坑）</b>：行业归属用申万（stock_sw_industry，如万华/卫星同为"化工"）；行业/产业 RS 是另一套中证 L2 产业分类（如 800材料/油气产业）——报告必须分开标注两套口径，禁止把"产业指数 RS"写成"化工行业 RS"，也禁止据此断言两股属不同行业
  - ④⑥ 两节合计应占正文 40%+，每个结论带具体数字
