# 指数研究方法论（index-research）

本技能约束**研究什么、怎么算、怎么判断结论能不能信**。
报告的排版、证据登记与封存见 `hanako-report`；两者必须同时满足。

**铁律：一切数字来自确定性脚本，模型不得估算、四舍五入或补全。**
**铁律：每个结论必须主动寻找反例；找不到反例的结论不得写成确定语气。**

---

## 一、要回答的核心问题（不是「这只指数好不好」）

研究一只指数的目的不是给它打印象分，而是回答四个可证伪的问题：

| # | 问题 | 不通过时的处理 |
|---|---|---|
| **Q1** | **它的收益从哪来？** 价格重估 / 分红 / 因子暴露，各占多少 | 若无法分解，说明它只是某个宽基的换皮。**Q1 的结论要在 §七「上涨本质总结」里落成一段话** |
| **Q2** | **它和谁像？** 相关性、持仓重叠、与海外的对应物 | 若相关度过高（R²>0.8），增量价值存疑 |
| **Q3** | **什么状态下买更好？** 回撤 / 估值 / RSI / 股息率 哪一维有区分力 | 若没有一维单调，则「择时」这个方向对它是错的 |
| **Q4** | **怎么卖？** 出场规则是否比入场更重要 | 若找不到正期望出场，结论只能是「持有」而非「波段」 |

**Q1~Q4 全部答完才算研究完成。只回答 Q1 就写报告，是把数据当结论。**

## 二、数据准备与口径（先定口径，再算数）

### 2.1 必须区分的三种收益口径

| 口径 | 含义 | 用在哪 |
|---|---|---|
| **全收益（TR）** | 含分红再投 | 所有收益类结论的**默认口径** |
| **价格指数** | 不含分红 | 只在明确讨论「价格波动」时用 |
| **分红贡献** | TR − 价格 | 用来回答 Q1，通常表示为 pp 或占比 |

**禁止用价格指数算长期年化后与全收益基准比较**——高股息指数会凭空少掉 3~5pp/年。

**已知数据事实**：本地只有 12 只指数有全收益序列（`index_full_return_daily`）。
**其余指数若要做全收益结论，必须先用 `scripts/fetch_index_full_return.py` 补齐，
否则结论只能写「价格口径」，并在报告中显式标注。**

### 2.2 常用数据表

| 表 | 内容 | 注意 |
|---|---|---|
| `index_daily_kline` | OHLCV | `kline_type='normal'`；空值需在 `load()` 里过滤 |
| `index_full_return_daily` | 全收益收盘 | 覆盖极少，先查再决定口径 |
| `index_fundamental_daily` | PE/PB/股息率 | **覆盖参差**：980092 只有 2024-09 起 501 行，**算不出「十年分位」** |
| `index_rs_daily` | 相对强度百分位 + MA50/150/200 | `rs_XX` 是**横截面百分位 0-100**，不是比值 |
| `index_constituents` / `index_constituent_weightings` | 成分与权重 | 用于计算重叠度 |

### 2.3 数据缺口必须在报告里显式声明

**格式（放进附录）：**

```
| 指标 | 可用区间 | 行数 | 结论影响 |
|---|---|---|---|
| 估值分位 | 2024-09-18 ~ 2026-10-16 | 501 | 不足以计算十年分位，不参与打分 |
```

**任何「N 年分位」类指标，先确认数据跨度 ≥ N×1.5 年。不够就换成「可用区间分位」并改名。**

## 三、标准分析菜单（Q1~Q4 的落地）

按顺序做，前一项的结论决定后一项是否还值得做。

### 3.1 收益分解（Q1）

```
全收益 CAGR、价格 CAGR、分红贡献 pp 与占比
对照：同区间宽基（如沪深300）、同类（如中证红利）
最大回撤、年化波动、下行捕获（分时段）
```

**输出到证据快照，报告里用一张对照表 + 一段归因。**

### 3.2 相似度与增量检验（Q2）

```
与候选对照指数的 R²（日收益回归）
成分重叠度：交集数量 / 并集数量，按权重口径再算一次
海外对应物：若有（如 COWZ / SCHD / VOO），给同口径对照
```

**判定门槛（本项目经验值，不是行业标准）**：
- `R² > 0.8` 且重叠 > 50% → 增量存疑，必须在报告里明说
- `R² > 0.8` 但重叠 < 20% → 相关来自风格暴露而非持仓，值得深挖

### 3.2.1 必备图表（一）：基准对比三线图

**任何指数研究都必须选一个基准做对比，且必须用折线图展示，不能只有文字结论。**

**三条曲线，全部归一到起点 = 100，同轴叠加：**

| # | 曲线 | 数据源 |
|---|---|---|
| 1 | **待研究指数的价格指数** | `index_daily_kline` |
| 2 | **待研究指数的全收益指数** | `index_full_return_daily` |
| 3 | **基准指数的全收益指数** | `index_full_return_daily` |

**基准必须用全收益口径，不能拿基准的价格指数去比待研究指数的全收益。**
否则基准会被系统性低估 2~3pp/年，结论直接失真。

**为什么必须是三条而不是两条：**

- 待研究指数「价格 vs 全收益」的开口 → 说明**分红贡献占多少**
- 待研究全收益 与 基准全收益 的相对位置 → 说明**是否真的跑赢**
- 只画待研究指数价格 + 基准价格 → 看不到分红，也看不到真实的相对强弱

**交互要求（与 §3.5.1 一致）：**
- 三条线各有开关（含基准线单独开关）
- 提供一个「累计超额」视图开关：`待研究全收益 / 基准全收益 − 1`，
  纵轴切成百分比。**这是回答「它到底赢没赢」最快的方式。**
- **图例动态生成**，只列当前显示的曲线

**基准缺全收益序列时：** 先 `scripts/fetch_index_full_return.py` 补齐
（该脚本的 `INDICES` 列表里加代码后运行）。补不到就换一个有全收益的基准，
**不得用价格指数替代基准全收益而不加说明。**

### 3.2.2 必备图表（二）：成分重叠图

**成分重叠除了文字与表格，必须有一张图。表格给不出「占比悬殊」的直觉。**

**推荐做法：互斥划分的堆叠条。**

先做严格划分（各区互斥、合计 = 待研究指数成分总数）：

```
同时属于 基准A 与 基准B
仅属于 基准A
仅属于 基准B
两者都不属于（独有）
```

**为什么必须先做互斥划分：**
直接算「与 A 重叠 X%、与 B 重叠 Y%」时，X+Y 可能超过 100%——
因为存在**同时属于 A 和 B 的股票**。实测 A500：18 只股票同时属于沪深300 与 中证500，
若不处理，两个比例相加会到 94.8%，看似合理实则重复计数。

**图表要求：**
- 水平堆叠条，**色块宽度按真实只数等比**
- 每个色块内标注「只数 + 占比」（宽度够时）
- 图例列出四类的只数与占比，**合计必须为 100%**
- 下方标注成分总数

**判读门槛（对齐 §3.2）：**
- 独有占比 < 15% → **「它不是独立因子，而是基准的加宽版」**，必须在正文写明
- 独有占比 15~30% → 有一定独立性，需继续看 §3.6 二维交叉
- 独有占比 > 30% → 独立性较强，重点看它与基准的行业/风格差异

### 3.3 分年度表现（稳定性）

逐年给收益与排名。**目的不是展示，是发现「结论只在某几年成立」。**

### 3.4 锚定回撤分档（Q3 的核心）

**关键定义：回撤必须锚定「历史最高点」，不是「近期高点」。**

```
drawdown[t] = close[t] / max(close[:t+1]) - 1
```

分档（本项目沿用的档位）：`0~5% / 5~10% / 10~15% / 15~20% / 20~30% / 30~40% / 40~50% / 50%+`

**每档必须同时输出：段数、入场日中位年化、胜率、最大再回撤。**

**若某档「段数 < 3」，该档结论不得单独引用**——那是一个事件，不是统计。

### 3.4.1 必备章节：估值全景 + 财务全景（十图标准，不可省略）

**报告必须有独立的「估值全景」与「财务全景」两章，合计 10 张图，
每张图下必须有点评。只有一张汇总表是不够的——读者要看到路径，不是看到结论。**

#### A. 估值三图（走势 + 滚动十年分位带）

| 图 | 内容 |
|---|---|
| 1 | **PE-TTM** 走势 + 滚动十年 10%~90% 分位灰带 + 中位橙虚线 + 当前值蓝线 |
| 2 | **PB** 同上 |
| 3 | **股息率** 同上 |

**结构固定为三层：**`当前值曲线` + `分位灰带（10%~90%）` + `中位虚线`。
灰带让读者一眼看出「现在的值在历史上的什么位置」，比单看分位数字直观得多。

#### B. 财务七图（历年柱状）

| 图 | 指标 | 单位 |
|---|---|---|
| 4 | ROE | % |
| 5 | 每股收益 EPS | 元/股 |
| 6 | 营业收入 | 亿元 |
| 7 | 净利润（归母） | 亿元 |
| 8 | 净利润率 | % |
| 9 | 营业利润率 | % |
| 10 | A 股分红金额 | 亿元 |

**柱状，正绿负红（硬编码 `#10b981` / `#ef4444`），柱顶标数值，横轴为年份。**

#### C. 每张图下的点评（必填六项）

> 近十年均值 **X**　·　最高 **X**（标年份）　·　最低 **X**　·　当前 **X**
> 　·　同比 **±X%**　·　分位 **X%**（历史偏高/中性/偏低）
> **点评：**当前值处于 …，高于/低于均值 …，说明 …。

**六项缺一不可。** 只给「当前 X」而不给均值与分位，读者无法判断高低。

#### D. 数据来源与三个必须知道的坑

**估值三项**：`index_fundamental_daily`（`pe_ttm` / `pb` / `dyr` 及其 `_pct` 分位）。
该表通常只有 2016 年起 2,600 余行，**「十年分位」实际是「可用区间分位」**，需在正文说明。

**财务七项**：理杏仁 `POST /api/cn/index/fs/non_financial`。
**这是唯一可用的端点，三个坑必须记住：**

| 坑 | 错法 | 对法 |
|---|---|---|
| **端点** | `/index/fs/hybrid`（对指数返回空） | **`/index/fs/non_financial`** |
| **响应结构** | 当作 `{'data': [...]}` 取 `.get('data')` | **顶层就是列表**，直接当 list 用 |
| **时间跨度** | 一次拉全历史 → 报错「时间跨度不能超过10年」 | **按 ≤10 年分段**再合并 |

**指标代码（年频 `y.` 前缀）：**

```
y.ps.toi.t         营业总收入
y.ps.op.t          营业利润
y.ps.npatoshopc.t  归母净利润
y.m.roe.t          ROE（小数，需 ×100）
y.m.npatoshopc_ps.t 每股收益
y.m.np_s_r.t       净利润率（小数，需 ×100）
y.ps.op_s_r.t      营业利润率（小数，需 ×100）
y.ps.da_om.t       A 股分红金额（元，需 ÷1e8）
```

**实现入口**：`scripts/fetch_index_financials.py --code <代码>`，
写入 `index_financials_annual`。换任何指数代码可直接复用。

#### E. 周期行业的估值异常必须处理

**周期股在盈利低谷时 PE 会爆表甚至为负**（实测煤炭 2016 年 PE 在 −2929 ~ +3433 之间跳动）。

**处理三步：**
1. 剔除 `PE ≤ 0` 与 `PE > 150` 的异常值（负值＝亏损，无估值含义）
2. 纵轴用 **2%~98% 分位裁剪**，不用 min/max
3. 在正文说明剔除了多少条、为什么

**只做第 2 步不够**——分位裁剪后极端值仍会把曲线压成一条直线，必须先剔除失效值。

#### F. 这一章要回答什么

**不是展示数据，是回答「现在贵不贵、为什么贵」。**

区分两种「贵」：
- **估值扩张型**：盈利平稳但 PE 上升 → 市场情绪推动，可能均值回复
- **盈利下滑型**：分母崩塌导致 PE 被动抬升 → **更危险**，股价未必跌但基本面在恶化

**财务七图的作用正是区分这两者**：把营收/净利润/ROE 与 PE 放在一起看，
一眼就能判断 PE 高是因为「股价涨太多」还是「盈利跌太快」。

### 3.5 RSI 多周期（Q3 的第二维）

```
周期：6 / 14 / 20 / 60，默认展示 14
买点阈值：≥30 以下分档；卖点阈值：RSI20 用 78，其余用 80
```

**硬性禁令（本项目踩过的坑）：**
- **禁止用「相对分位」定义买卖点**（如 >p95）。它会让买卖标记数量随样本变化，无法跨指数比较。
- **禁止用固定 65/70 当卖点**。实测 RSI6 在 65 上会出现 250 个卖点、覆盖 1019 天，等于没筛选。
- **RSI 的结论必须绑定持有期，且必须逐指数重测，不可跨指数套用。**
  **不同指数的 RSI 结论可以完全相反**——实测：
  - 红利 / 自由现金流：RSI20 <30 的 20 日 +4.34%，250 日优势归零（−1.17pp）→ 买入侧有用
  - **中证A500：卖出侧 RSI20 ≥78 之后 120 日反而高于基准 +12.6pp** → 「高 RSI 卖出」是反效果的
  **禁止把某个指数上的 RSI 结论直接搬到另一个指数上，即使在同一条 skill 里。**

#### 3.5.1 必备图表：价格/全收益 × RSI 交互图（标准输出物，不可省略）

**RSI 章节必须内嵌一张交互图，不能只有表格。**

| 区域 | 内容 |
|---|---|
| **主图** | **价格指数** 与 **全收益指数** 两条曲线，**均归一到起点=100**，同轴对比 |
| **副图** | **RSI 曲线**，默认**只显示 RSI20 一条** |
| **副图参考线** | 30（买点）/ 50（中轴）/ 80（卖点，RSI20 用 78） |
| **交互 1** | RSI6 / RSI14 / RSI20 三个开关，**默认只开 RSI20**；用户可叠加显示 |
| **交互 2** | 价格 / 全收益 两条线各自独立开关 |
| **交互 3** | 「买卖点」开关，打开后在 RSI 曲线上打点：**买点 RSI≤30、卖点 RSI≥阈值（RSI20 为 78，其余 80）** |
| **图例** | **必须动态生成**：只列出当前实际显示的曲线，并标明各自卖点阈值 |

**硬性要求：**

1. **主图必须同时有价格与全收益两条线**，起点都归一到 100。
   两者的**开口就是分红贡献**，这是肉眼可见的核心信息。
   **若该指数缺全收益序列，先补齐再出图**（`scripts/fetch_index_full_return.py`
   的 `INDICES` 列表加入代码后运行）；补不到就在图下方显式标注缺口，**不得省略全收益线却不说明**。
2. **副图默认只显示 RSI20**。默认三条全开会让画面变成三色噪声，读者无法判断。
3. **图例不得写死**。图例与曲线必须由同一份状态驱动——
   否则会出现「图里只有 RSI20、图例写着 RSI14」的脱节。
4. **不依赖外部库**（对齐 §5.0）：用内联 SVG 或 Canvas + 原生 JS，
   数据在生成时算好并内嵌为 JSON，保证单文件离线可用。
   **不要为了画图引入 CDN 或把 ECharts 整个内嵌。**
5. **买卖点标注必须与阈值表一致**：图上标的点和 §3.5 表格里的触发次数应对得上，
   对不上说明阈值口径不一致。

**为什么主图要两条线：**
只画价格，读者看不到分红；只画全收益，读者感受不到波动。
**两条归一曲线并列，才能同时回答「它涨了多少」和「其中多少是分红」。**

### 3.6 增量检验：A 是不是 B 的替代品

把候选因子与对照因子做二维交叉：

```
二维表：行 = 因子A 分档，列 = 因子B 分档，格 = 未来收益中位 + 样本数
```

**看的是「控制 B 之后 A 还有没有区分力」。**
若同一 B 档内 A 各档收益无差异 → A 是 B 的影子。

### 3.7 案例复盘（让人相信结论的锚）

挑 2~3 个标志性时点（历史极值 / 最近的极端事件），把指标、当时可得的结论、事后的实际结果并列。

**案例不能只挑成功的。必须至少有一个「按规则做会难受」的案例。**

### 3.8 资金到位回测（Q4）

**按固定节奏投入**（每月 / 每季 / 每年）的定投回测，起点做敏感性扫描：

```
对不同起点（每年 1 月起投）分别算 XIRR / 年化
报告：中位、最好、最差 —— 而不是只报一个「最优起点」
```

**只报最优起点是最常见的自欺。**

### 3.9 投资方法对比

`一直持有 / 深跌加倍 / 定投 / 择时` 等方法在同一区间的对照，把「回测好看」和「能执行」分开说。

### 3.10 分析菜单执行核对（强制执行，不可跳过）

**在写报告之前，逐项打勾。任何一项未执行，必须写明「跳过原因」，否则视为研究未完成。**

| 3.1 | 收益分解（TR / 价格 / 分红） | ☐ | |
| 3.2 | 相似度与增量检验（R² / 重叠 / 海外对应） | ☐ | |

| 3.2.2 | **成分重叠图**（互斥划分堆叠条） | ☐ | |

| 3.4.1 | **估值全景 3 图 + 财务全景 7 图（含点评）** | ☐ | |
| **3.5** | **RSI 多周期（6/14/20/60）** | ☐ | |

**不可接受的跳过理由：**
- 「忘了」
- 「时间不够」
- 「看起来不重要」

## 四、回测的可信度规则（这一章比上面所有分析都重要）

### 4.1 持有期口径：区间收益 > 固定持有期

**固定 20/60/120/250 日会跨越状态边界，收益被下一个状态污染。**

**正确做法：按「进入某状态 → 离开该状态」计算区间收益。**

| 指标 | 定义 |
|---|---|
| 区间收益 | `close[离开前一日] / close[进入当日] − 1` |
| 区间胜率 | 区间收益 > 0 的占比 |
| 中位时长 | 区间的交易日数 |

**当区间中位时长 < 5 日时，区间收益统计接近噪声，必须改用策略层口径（见 4.2）。**

### 4.2 决策相关指标：策略层，不是阶段层

只报「各阶段平均涨跌」没有决策价值。要报：

```
买入规则 × 出场规则 → 笔数 / 胜率 / 单笔中位 / 盈亏比 / 期望每笔 / 中位持有
```

**必须同时给「全样本」与「样本外（建议 2020 起）」两列。**

### 4.3 胜率不是重点，盈亏比才是

趋势类系统的典型形态是 **胜率 50% 上下、盈亏比 2~3 : 1**。
**只报胜率会得出完全相反的结论。**

**例**：②进⑥出 胜率 51.3% 看着还行，但单笔中位 +0.48%、期望 +4.16%；
拆开看盈利笔 +12.70%、亏损笔 −4.84%——价值全在盈亏比。

### 4.4 样本独立性：笔数 ≠ 独立事件

**指数之间高度相关（同属 A 股时尤甚）。**

报告里凡出现笔数，必须加一句独立性说明：

> 393 个指数高度相关，有效独立事件数远小于笔数，胜率不可直接外推。

**同一时段不同指数上的 1000 笔交易，可能只有 1~2 个独立市场周期。**

### 4.5 存活偏差：未平仓的单子必须计入

策略回测里「没等到出场信号」的单子不能被丢掉。

**必须报告：未平仓笔数与占比，并按期末价计入后重算合并胜率。**

**例**：某规则已平仓胜率 72.4%，未平仓 4.2%（胜率 4.4%、中位 −15.5%），
合并后 69.6%——**结论仍成立，但不做这一步就不知道它成立。**

### 4.6 未来视角：必须做截断检验

**原理**：若判定只用截至当日的数据，则「用截至 T 日的数据」与「用全量数据」
算出的 T 日结果必须完全一致。

**做法**：随机抽 20~30 个时点，把序列截到该时点重跑，逐点比对。

**结果要求：不一致数 = 0。**
**已知的高发错误**：基准窗口写了 `c[i-20:i+1]`（含当日），导致 `close > max(...)` 永假。

### 4.7 分档的样本量下限

| 段数 | 处理 |
|---|---|
| ≥ 10 | 可作结论 |
| 3 ~ 9 | 可提及，须标注「样本有限」 |
| < 3 | **不得单独引用**，只能作为案例 |

## 五、产出编排


### 5.0 输出格式：一律 HTML（硬性要求）

**所有研究产出都是单文件 HTML，不是 Markdown。**

| 产出 | 路径 | 说明 |
|---|---|---|
| 研究报告 | docs/report/<报告名>/index.html | 单文件，内嵌 CSS，可离线打开 |
| 生成器 | docs/report/make_<前缀>_report.py | 可重复运行，每个数字现算 |
| 图表 | docs/report/<报告名>/images/<前缀>_<名称>.png | 前缀与本报告一致 |

**为什么不用 Markdown：**
- 研究结论必须带大量表格与图表，Markdown 的表格无法承载多列数字对照
- 需要 KPI 卡片、涨跌配色、可折叠附录等排版能力
- 交付对象是「能直接看」而不是「能直接改」

**HTML 必须满足：**
- 单文件、内嵌 <style>，不依赖外部 CSS/JS/CDN
- 深色底 #0e0e12 / 卡片 #16161d / 描边 #2a2a33
- **涨跌配色硬编码**：涨 #10b981、跌 #ef4444，禁止用 CSS 变量替代
- 表格数字用等宽数字（ont-variant-numeric: tabular-nums）
- 移动端不横向溢出（<table> 外层包 .tw{overflow-x:auto}）
- 顶部固定：标题、数据截止日、口径声明、缺口声明

**KPI 卡片**放最关键的四到六个数字，让读者三秒内抓住结论。

## 七、上涨本质总结（强制产出，不可省略）

### 7.1 为什么必须做

分档、RSI、相关性都能算出数字，但回答不了**「我为什么该长期持有它」**。
**每研究完一只指数，必须产出一段能独立成立的本质总结。写不出来，说明研究没做完。**

### 7.2 强制格式：三段式，缺一不可

**第一段 · 一句话本质（≤ 40 字，不含具体数字）**

> 例：「它的收益来自高现金流企业把利润分掉，不是来自估值提升。」
> 反例：「它长期表现优秀，值得关注。」——**没有信息量，视为未完成。**

**第二段 · 三段分解（每段必须带数字）**

| 分项 | 要求 |
|---|---|
| **钱从哪来** | 全收益 = 分红贡献 + 盈利增长 + 估值变动，各是多少 pp、占比多少 |
| **为什么持续** | 判明是**结构性**（编制规则、产业趋势、政策）还是**周期性**（风格轮动、利率环境） |
| **什么时候失效** | 给出**可观测**的失效条件，不是「市场有风险」这种空话 |

**第三段 · 可推翻条件**

> 「若出现 X，则上述判断不成立。」

**必须具体到可观测事件**。例：「若成分股分红率整体降到 30% 以下，
则分红贡献无法维持 3.8pp，本结论失效。」

### 7.3 先做收益恒等式，再写结论

```
全收益 CAGR ≈ 股息率 + 盈利增速 + 估值变动年化
```

**三项相加与实测全收益的差额 > 2pp 时，说明分解不完整**（可能有成分调整、
汇率、编制规则变化），**必须查明原因后才能下本质判断**。

### 7.4 四种本质类型与判据

| 本质类型 | 判据 | 含义与风险 |
|---|---|---|
| **分红型** | 分红贡献 ≥ 全收益的 40% | 收益可重复、但增长有限；风险是分红政策变化 |
| **成长型** | 盈利增长贡献 ≥ 全收益的 50% | 依赖产业趋势，周期性强；风险是景气反转 |
| **重估型** | 估值变动贡献 ≥ 全收益的 40% | **一次性，不可外推**；把重估当能力是常见误判 |
| **结构型** | 收益主要来自成分调整 / 编制规则变化 | 需检查是否存在幸存者偏差；**这是最危险的一类** |

**混合型必须给出各项占比，不得只贴一个标签。**
**占比之和与 100% 的差额要交代清楚去了哪里。**

### 7.5 输出位置

| 载体 | 形式 |
|---|---|
| 研究报告 | **独立一章，放在「结论」之前** |
| 小红书笔记 | 作为收尾段落，用普通人能懂的话重述（可用比喻，但数字不能改） |
| 产品页面 | 作为该指数的「一句话说明」，与阶段/评分并列展示 |

### 7.6 反例要求

**本质总结必须包含至少一个「按这个本质去操作会亏钱的情形」。**

写不出反例，说明总结还不够具体——**它描述的是印象，不是机制**。

例：「按『分红型』理解它会亏的情形：分红率维持但股价因估值收缩下跌 30%，
此时分红再投也救不了当年的账户——2021~2024 年中证红利就发生过。」

### 7.7 完成判据

以下四条全部满足，才允许在报告中写「研究完成」：

- [ ] 一句话本质 ≤ 40 字，且不含具体数字
- [ ] 三段分解都有数字，三占比之和与 100% 的差额已交代
- [ ] 失效条件可观测、可验证
- [ ] 有一个具体的「会亏钱的情形」

## 九、研究一只新指数的最短路径

```
1. 查数据：有全收益吗？估值序列够长吗？          → 定口径
2. 收益分解：TR / 价格 / 分红，对照宽基            → 回答 Q1
3. 相似度：R² + 重叠度 + 海外对应物                → 回答 Q2
4. 分年度：结论是否只在某几年成立                  → 稳定性
5. 锚定回撤分档 + RSI 多周期                       → 回答 Q3
6. 二维交叉：控制变量后还剩什么                    → 增量
7. 资金到位回测（起点敏感性）                       → 回答 Q4
8. **写上涨本质总结（§七，三段式）**
9. 出报告 + 出笔记 + 落产品
```

**每一步的中间结果都写进证据快照。第 5 步若某维不单调，就是「该维度对这只指数无效」，
这本身是结论，不要为了凑出规律而调参数。**
