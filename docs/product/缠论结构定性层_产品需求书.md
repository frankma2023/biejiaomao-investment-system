# 缠论结构定性层 — 产品需求书

> 版本：v1.0 · 日期：2026-05-31

## 一、问题定位

### 1.1 现状

当前缠论引擎的 pipeline 是机械的：

```
分型 → 笔 → 线段 → 中枢 → 背驰 → 买卖点 → 输出信号
```

这条流水线在**形态学**层面做得很好——笔、线段、中枢画得精准。但在**动力学**和**结构定性**层面，引擎完全缺失判断力。

### 1.2 核心矛盾

同一个底背驰（一买）信号，发生在不同结构位置，含义完全不同：

| 结构位置 | 信号含义 | 操作价值 |
|---------|---------|---------|
| 周线下跌末端 + 日线底背驰 | 大小级别共振，反转概率最高 | 🟢 高 |
| 日线上涨趋势中继回调 + 底背驰 | 中继买点，顺势操作 | 🟡 中 |
| 日线中枢震荡中 + 底背驰 | 盘整背驰，震荡区间内 | 🟠 低 |
| 日线顶部区域 + 底背驰 | 反弹，不是反转 | 🔴 极低 |

引擎不做区分，全部作为"一买"信号发出。回测差的原因不在于缠论理论本身，而在于**缺乏结构定性层的过滤**。

### 1.3 结论

不是放弃机械信号，而是在信号发出前加一层**结构定性**。信号和结构的匹配关系，才是缠论有效使用的关键。

---

## 二、架构设计：结构定性层

### 2.1 定位

结构定性层位于**形态学（画线）和信号输出之间**：

```
┌─────────────┐
│ 形态学       │ ← 已有：分型、笔、线段、中枢（画得好，不改）
│ (morphology) │
└──────┬──────┘
       │
┌──────▼──────┐
│ 结构定性层    │ ← 新增：级别、位置、方向、阶段（核心投入）
│ (structure)  │
└──────┬──────┘
       │
┌──────▼──────┐
│ 动力学       │ ← 已有：背驰、买卖点（改变触发逻辑）
│ (dynamics)   │
└──────┬──────┘
       │
┌──────▼──────┐
│ 信号过滤器    │ ← 新增：结构+背驰匹配、信号分级
│ (filter)     │
└──────┬──────┘
       │
       ▼
    输出信号（分级：强/中/弱/抑制）
```

### 2.2 核心原则

- **画线不改**：分型、笔、中枢的算法已经成熟，不做调整
- **信号不发**：不改变背驰判定的数学逻辑
- **只在中间加一层判断**：信号发出前，先问"当前在什么结构位置上？"

## 三、结构定性维度

### 3.1 三个核心问题

对任意股票的任意时刻，结构定性层回答三个问题：

| 问题 | 判定维度 | 输出 |
|------|---------|------|
| Q1: 它在大级别上处于什么阶段？ | 周线笔方向 + 中枢位置 | `trend_up` / `trend_down` / `consolidation` |
| Q2: 它在当前级别上处于什么位置？ | 日线笔方向 + 与中枢的关系 | `above_zs` / `inside_zs` / `below_zs` / `no_zs` |
| Q3: 两个级别的方向关系？ | 周线 vs 日线笔方向 | `共振向上` / `共振向下` / `大顺小逆` / `大逆小顺` |

### 3.2 级别体系

使用已有的多周期数据（日/周/月K线），不做新的合成：

- **本级**：日线（操作级别，信号触发级别）
- **上级**：周线（结构判断级别，定战略方向）
- **参考级**：月线（极端位置辅助，不参与常规信号判定）

### 3.3 位置分类

基于笔和中枢的关系，将当前位置分为六类：

| 位置代码 | 含义 | 判定规则 |
|---------|------|---------|
| `TREND_UP_END` | 上涨末端 | 上级笔向上 + 本级别出现顶背驰 |
| `CONSOL_UPPER` | 中枢上沿 | 在最后一个中枢内 + 接近中枢上沿(ZG) |
| `CONSOL_LOWER` | 中枢下沿 | 在最后一个中枢内 + 接近中枢下沿(ZD) |
| `CONSOL_MID` | 中枢中间 | 在最后一个中枢内 + 在 ZG/ZD 之间 |
| `BREAKOUT_UP` | 向上突破中 | 离开中枢向上 + 未形成三买确认 |
| `BREAKOUT_DOWN`| 向下突破中 | 离开中枢向下 + 未形成三卖确认 |
| `TREND_DOWN_END`| 下跌末端 | 上级笔向下 + 本级别出现底背驰 |
| `FREE_FALL` | 单边下跌 | 无有效中枢 + 方向向下 |
| `FREE_RISE` | 单边上涨 | 无有效中枢 + 方向向上 |

### 3.4 阶段判定

| 阶段 | 特征 | 操作原则 |
|------|------|---------|
| **筑底区** | 下跌末端 + 中枢形成中 | 等待一买确认，不急 |
| **拉升区** | 中枢突破 + 方向向上 | 买点信号积极采纳 |
| **中继区** | 中枢震荡中 | 只做中枢下沿的波段买点 |
| **赶顶区** | 上涨末端 + 顶背驰 | 抑制所有买点信号 |
| **派发区** | 下跌趋势中 | 不发出买点信号 |

## 四、信号分级与匹配规则

### 4.1 信号分级

根据结构位置，同一背驰信号被分为四个等级：

| 等级 | 条件 | 操作建议 |
|:--:|------|---------|
| ⭐⭐⭐ | 大小级别共振 + 结构位置正确 | 主力买入信号 |
| ⭐⭐ | 本级结构好 + 上级无冲突 | 辅助买入信号 |
| ⭐ | 本级有信号 + 上级不配合 | 仅观察 |
| — | 上级明确反向 | **抑制，不发出** |

### 4.2 匹配矩阵

买卖点信号 × 结构位置的判定矩阵：

| 背驰信号 → | 一买 | 二买 | 三买 | 一卖 | 二卖 | 三卖 |
|结构位置↓ | | | | | | |
| `TREND_DOWN_END` | ⭐⭐⭐ | ⭐⭐ | — | — | — | — |
| `CONSOL_LOWER` | ⭐⭐ | ⭐⭐⭐ | ⭐ | — | — | — |
| `CONSOL_MID` | ⭐ | ⭐⭐ | ⭐ | ⭐ | ⭐⭐ | ⭐ |
| `CONSOL_UPPER` | — | ⭐ | ⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐ | ⭐ |
| `TREND_UP_END` | — | — | — | ⭐⭐⭐ | ⭐⭐ | — |
| `BREAKOUT_UP` | — | — | ⭐⭐⭐ | — | — | ⭐ |
| `FREE_FALL` | ⭐⭐ | ⭐ | — | — | — | — |
| `FREE_RISE` | — | — | ⭐⭐ | ⭐⭐ | ⭐⭐⭐ | ⭐ |

> `—` = 信号被抑制，不发出

## 五、工程实现路径

### 5.1 Phase 1：结构快照（1-2天）

**目标**：在缠论分析页面展示结构定性，不改变信号逻辑。

**改动**：
- `chanlun.py` 新增 `describe_structure(bi_list, zs_list, freq)` 函数
- 输出 `structure_summary` 字段到 API 响应
- 前端展示结构描述卡片

**判定规则（Phase 1 用简单启发式）**：
```python
def describe_structure(bi_list, zhongshu_list, freq="D"):
    last_bi = bi_list[-1]
    last_zs = zhongshu_list[-1] if zhongshu_list else None

    direction = "向上笔" if last_bi.direction == "up" else "向下笔"

    # 判断与中枢的关系
    if last_zs:
        zg, zd = last_zs.zg, last_zs.zd
        current_price = last_bi.high if last_bi.direction == "up" else last_bi.low
        if current_price > zg:
            position = "中枢上方"
        elif current_price < zd:
            position = "中枢下方"
        else:
            position = "中枢内部"
        zs_info = f"最近中枢: {zd:.1f}~{zg:.1f}"
    else:
        position = "无中枢"
        zs_info = ""

    return {
        "direction": direction,
        "position": position,
        "zs_info": zs_info,
        "summary": f"{direction} · {position} · {zs_info}"
    }
```

### 5.2 Phase 2：多级别联动（3-5天）

**目标**：在单个级别结构快照的基础上，加入上级（周线）的结构判断。

**改动**：
- `get_echarts_option` 同时查询周线数据
- 新增 `compare_levels(day_structure, week_structure)` 输出共振关系
- 前端展示"周线趋势：向下 → 日线底背驰属于大逆小顺，信号降级"

### 5.3 Phase 3：信号过滤器（1周）

**目标**：根据结构位置自动过滤和分级信号。

**改动**：
- 新增 `filter_signals(signals, structure)` 函数
- 实现 4.2 节的匹配矩阵
- 信号输出加 `grade` 字段（3星/2星/1星/抑制）
- 前端信号列表展示等级和抑制原因

### 5.4 Phase 4：回测验证（可选）

**目标**：用历史数据验证过滤器是否提升了信号胜率。

**改动**：
- 在回测框架中加入结构定性层的过滤
- 对比过滤前后的信号收益率

## 六、与欧奈尔体系的分工

```
欧奈尔 (CANSLIM)          缠论 (结构+信号)
─────────────────         ─────────────────
选股 (What to buy)        择时 (When to buy)
量化评分、排序             结构定性 + 信号匹配
池子基本面过滤              买卖点分级
行业RS排名                 仓位大小建议
机械执行                   人工判断辅助

交集：欧奈尔出池的股票 + 缠论判定为可操作结构 → 执行
```

两者的协作不是"信号叠加"（1+1），而是**两阶段过滤**：
1. 欧奈尔选出基本面+动量达标的候选池
2. 缠论结构定性层过滤掉"不在买点区域"的候选
3. 剩余的少量候选进入人工决策环节

### 6.1 阶段划分定位

欧奈尔体系负责**选股/建池**（what），缠论负责**择时**（when），与阶段匹配：

| 欧奈尔信号 | 缠论结构匹配 | 买入后进入的阶段 |
|-----------|------------|----------------|
| 基部突破 | 筑底区/中枢下沿 | 持仓监控 |
| 口袋支点 | 拉升区/中枢突破 | 持仓监控 |
| 追盘日确认 | 筑底区完成 | 持仓监控 |

| 缠论卖点 | 欧奈尔卖出规则匹配 | 触发后行动 |
|---------|-------------------|-----------|
| 一卖(顶背驰) | 放量触顶、龙头股见顶、大盘走弱 | 减仓/清仓 |
| 二卖(反弹不破前高) | 跌破关键均线、抛盘日累积 | 减仓 |
| 三卖(反弹不破中枢下沿) | 趋势破位、AD/NH-NL恶化 | 清仓 |

> **买入端**：以欧奈尔的买入信号为主，缠论的结构位置做**准入过滤**；
> **卖出端**：不需要再引入缠论卖点。**欧奈尔的卖出规则和评分卡已经足够**——如果结构走坏，抛盘日累积、均线破位、龙头股见顶等信号会先于缠论卖点触发。两个体系都指向卖出时，可信度最高。

最终形成闭环：**欧奈尔选股 → 缠论择时（检查结构位置是否在买点区域）→ 欧奈尔评分卡决定仓位 → 欧奈尔卖出规则执行卖出**。整体工作流如下：

```
步骤1 — 欧奈尔选股（每周末）
  ├─ 股票精选六层筛选 → 候选池
  └─ 指数精选四层筛选 → 判断大盘环境

步骤2 — 缠论结构扫描（每日）
  ├─ 对候选池中的股票逐个扫描日线+周线结构
  ├─ 结构定性层判断当前位置
  └─ 输出：⛔ 禁止买入 / 🟡 观察 / 🟢 可操作

步骤3 — 买卖决策（每日）
  ├─ 欧奈尔信号触发(基部突破/口袋支点) + 缠论结构允许 → 执行买入
  ├─ 欧奈尔评分卡决定仓位大小
  └─ 大盘卖出评分卡检查是否需要减仓

步骤4 — 持仓监控（每日）
  ├─ 欧奈尔卖出规则检查(止损/均线/抛盘日)
  └─ 缠论结构变化预警(中枢破坏/三卖出现)
```

## 七、FAQ

**Q: 为什么不直接用缠论买卖点，还要保留欧奈尔的？**

欧奈尔的 CANSLIM 是可量化的、有明确阈值的体系。缠论是读图的、需要经验判断的。在买入端，欧奈尔选股 + 缠论检查结构位置 = 双重保险。在卖出端，欧奈尔的卖出规则更明确、更易执行。

**Q: Phase 1 的结构判定太简单了，准确吗？**

Phase 1 的目标不是100%准确，而是让用户**看到结构背景**。即使判定有误差，用户看到"当前中枢位置+笔方向"也能自己做判断。这比不看结构只盯信号好得多。

**Q: 这个方案需要多长的历史数据？**

日线400根 + 周线200根，约2年的数据。现有的 `chanlun.py` 已经在用这个数据量，不需要额外拉取。
