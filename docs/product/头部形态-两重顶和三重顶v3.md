# 头部形态：双重顶与三重顶

## 1. 概述

双重顶（Double Top，又称M头）和三重顶（Triple Top）是经典的技术反转形态，出现在上升趋势末端。它们由多个大致相同高度的顶部和中间的回调低谷构成，形状像字母"M"或更复杂的波浪形态。当价格跌破这些低谷的连线（颈线）时，确认反转。

这些形态反映了买方力量从强到弱、卖方力量逐渐主导的全过程：多方多次冲击阻力失败，卖压逐渐积累，最终导致趋势逆转。

```
双重顶图示：

        A(左顶)              B(右顶)
          /\                  /\
         /  \                /  \
        /    \              /    \
       /      \            /      \
      /        \__________/        \
     /                          ______\
    /                          \
   /                            \
  /                              \
 /                                \
/                                  \
            ↑颈线↑
        (中间低谷的最低点)


三重顶图示：

        A(左顶)      B(中顶)      C(右顶)
          /\          /\          /\

 /                                           \
/                                             \
              ↑颈线↑（谷1和谷2的最低点）
```

## 2. 双重顶（Double Top）

### 2.1 定义与特征

双重顶由两个大致相同高度的顶部组成，中间有一个回调低谷。它是头肩顶的简化版本，出现频率高于三重顶。

| 特征 | 量化规则 | 说明 |
|------|----------|------|
| 两个顶部 | 两个高点价格差异 ≤ 3% | 左右顶高度应相近，否则不是真正的双重顶 |
| 顶部间隔 | 两顶之间至少间隔15个交易日 | 避免把短期的小波动误认为双顶，周线则至少3周 |
| 中间低谷 | 从第一个顶回调幅度 ≥ 8%（可配置6%-12%） | 必须有明显的下跌过程，否则只是横盘整理 |
| 颈线 | 两个顶部之间的最低点（深谷的最低价） | 双重顶只有一个深谷，颈线为该深谷的最低价 |
| 跌破颈线 | 收盘价低于颈线3%以上，**或**连续3日低于颈线 | 确认反转 |

### 2.2 为什么需要这些条件？

#### 2.2.1 价格相近（≤3%）的原因

如果两个顶的高度相差太大（比如右顶比左顶高5%以上），说明多方力量仍然强劲，股价仍在创出新高，这不是双重顶，而是上升趋势的延续。真正的双重顶应该显示多方力量衰竭，无法突破前高。

#### 2.2.2 时间间隔（≥15天）的原因

太短的时间间隔（如3-5天）通常只是短期波动，不是真正的趋势反转。欧奈尔体系中的基部构建至少需要5-10周（25-50天），双重顶作为反转形态，也需要足够的时间来反映机构出货的过程。

#### 2.2.3 中间回调幅度的讨论

关于中间回调幅度，存在不同的观点：

- **保守模式（10%）**：减少误报，适合高胜率策略
- **标准模式（8%）**：平衡误报与漏报，A股波动大时推荐
- **宽松模式（6%）**：捕获更多形态，适合快速扫描

参考依据：
- Bulkowski对双重顶的统计中，中间回调幅度无硬性下限，但典型值在5%-15%
- 欧奈尔体系对"明显回调"的界定通常为10%-15%
- A股波动较大，8%可作为平衡值

**实现建议**：将回调幅度做成可配置参数，便于回测优化。

```yaml
double_top:
  min_retracement: 0.08   # 默认8%，可配置0.06-0.12
```

### 2.3 检测流程

#### 第1步：确定上升背景前提（仅左顶需要）

在检测双重顶之前，需要确认**左顶所在的位置曾经处于上升趋势中**。如果股票一直处于下跌或横盘，出现的"双顶"只是下跌中的反弹结构，没有预警意义。

**核心原则：只验左顶的上升背景，右顶不验。**

为什么右顶不验？因为右顶本身就是回调后的反弹——这正是双重顶形态的定义特征。如果要求右顶也必须有上升背景，那所有双重顶都会被过滤掉。

**检测规则**：

左顶的上升背景检查条件（满足任一即可）：
- 60天内盘中 low→high 涨幅 ≥ 20%（方向性验证：高点必须出现在低点之后）
- MA50 在过去10天内曾向上

注意：
- 方向性验证：高点必须在低点之后
- 右顶不验上升背景：双重顶本身就是上升趋势的终结形态。只要起点是上升趋势，中间的波动（哪怕顶 2 不再创新高且 MA50 走平）就是形态的一部分

##### 为什么用 low→high 而不是 close→close？

很多顶部都有较长的上影线，这也是机构出货的标志。如果只以收盘价到收盘价来计算涨幅，可能涨幅不满足条件；但如果以最低价的下影线到最高价的上影线来计算，就满足了。使用盘中的 full range（low→high）更真实地反映了股价的波动幅度。

##### 为什么用 MA50 而不是 MA200？

MA50 比 MA120/MA200 灵敏得多。在实际回测中发现：
- **MA200 在下跌初期仍微弱向上**——一只股票从100跌到80，MA200可能只差1块钱就"向上"，让下跌途中的反弹峰错误通过背景检查
- **MA50 在下跌途中通常已经向下**——能正确区分"上升趋势中的峰"和"下跌反弹中的峰"

##### 为什么涨幅阈值是20%而不是30%？

A股大盘股的波动幅度通常小于小盘股。30%对大盘股过于苛刻，会把一些真实的顶部过滤掉。20%在回测中对万华化学（600309）等大盘股也能正确识别。

##### 方向性验证：高点必须在低点之后

这是最容易被忽略的陷阱。考虑这个场景：

```
股价走势：100 → 101 → 79 → 96
          (高点)          (低点)  (反弹)
```

如果只看60天窗口内的 max/min 比值，会算出"涨幅" = (101 - 79) / 79 = 27.8%，
但高点101出现在低点79**之前**！这不是"从79涨到101"，而是"先涨到101→跌到79→反弹到96"。

**必须验证：高点的日期 > 低点的日期，才计入涨幅。**

```python
def _peak_has_uptrend_background(self, peak_idx, highs, lows, dates, ma50_series):
    """
    检查左顶的上升背景（仅用于左顶）
    
    条件（满足任一即可）：
    1. 60天内盘中 low→high 涨幅 ≥ 20%（方向性验证）
    2. MA50 在过去10天内曾向上
    
    Args:
        peak_idx: 左顶在数据中的索引位置
        highs: 盘中最高价序列
        lows: 盘中最低价序列
        dates: 日期序列
        ma50_series: MA50均线序列
    """
    lookback_days = 60
    min_gain = 0.20  # 20%
    
    # === 条件1：方向性涨幅验证 ===
    start_idx = max(0, peak_idx - lookback_days)
    window_highs = highs[start_idx:peak_idx + 1]
    window_lows = lows[start_idx:peak_idx + 1]
    window_dates = dates[start_idx:peak_idx + 1]
    
    high_val = float(max(window_highs))
    low_val = float(min(window_lows))
    high_pos = list(window_highs).index(high_val)
    low_pos = list(window_lows).index(low_val)
    
    # 关键：高点必须在低点之后
    if high_pos > low_pos:
        directed_gain = (high_val - low_val) / low_val
        if directed_gain >= min_gain:
            return True
    
    # === 条件2：MA50 方向验证 ===
    ma50_lookback = 10
    if peak_idx >= ma50_lookback and ma50_series is not None:
        ma50_at_peak = float(ma50_series[peak_idx])
        ma50_before = float(ma50_series[peak_idx - ma50_lookback])
        if ma50_at_peak > ma50_before:
            return True  # MA50 在10天内曾向上
    
    return False
```

这样既能保证形态出现在上涨背景之后，又不会因为当前已经转弱而漏掉预警信号。

#### 第2步：识别局部高点和低点（峰谷检测）

这是双重顶检测的核心。需要找到价格序列中的局部高点和低点。

**检测规则**：
- 局部高点：比前后各N个交易日（默认5天）的最高价都要高
- 局部低点：比前后各N个交易日的最低价都要低
- **峰值突出度**（prominence）：峰值相对于周围低点的突出程度 ≥ 3%（可配置），过滤噪音峰
- 回溯窗口：最远200天，超过的形态对当前操作无指导意义

| 参数 | 推荐默认值 | 说明 |
|------|-----------|------|
| `peak_detection_window` | 5 | 峰谷检测窗口（前后各5天） |
| `peak_prominence` | 0.03 | 峰值突出度阈值（3%） |
| `max_lookback_days` | 200 | 最远回溯200个交易日（约10个月） |
| `min_lookback_days` | 60 | 最少需要60天数据才能检测 |
| `peak_window_days` | 60 | 谷两侧找峰的时间窗口 |

```python
def find_peaks_troughs(df, window=5, prominence=0.03):
    """
    识别局部高点和低点，带突出度过滤
    
    Args:
        df: 日线数据（需含 high, low, date 列）
        window: 前后比较窗口天数
        prominence: 峰值最小突出度（0.03 = 3%）
    """
    highs = df['high']
    lows = df['low']
    
    raw_peaks = []
    raw_troughs = []
    
    for i in range(window, len(df) - window):
        # 局部高点：比前后各window天的最高价都要高
        window_high = max(highs.iloc[i-window:i+window+1])
        if highs.iloc[i] >= window_high:
            raw_peaks.append({
                'idx': i,
                'price': float(highs.iloc[i]),
                'date': df['date'].iloc[i]
            })
        # 局部低点：比前后各window天的最低价都要低
        window_low = min(lows.iloc[i-window:i+window+1])
        if lows.iloc[i] <= window_low:
            raw_troughs.append({
                'idx': i,
                'price': float(lows.iloc[i]),
                'date': df['date'].iloc[i]
            })
    
    # 突出度过滤：峰必须比相邻谷高出 prominence 比例
    peaks = []
    for p in raw_peaks:
        # 找该峰前后最近的谷
        left_troughs = [t for t in raw_troughs if t['idx'] < p['idx']]
        right_troughs = [t for t in raw_troughs if t['idx'] > p['idx']]
        nearest_trough_price = None
        if left_troughs:
            nearest_trough_price = left_troughs[-1]['price']
        if right_troughs:
            rt = right_troughs[0]['price']
            if nearest_trough_price is None or rt > nearest_trough_price:
                nearest_trough_price = rt
        if nearest_trough_price and (p['price'] - nearest_trough_price) / nearest_trough_price >= prominence:
            peaks.append(p)
    
    # 谷也做突出度过滤
    troughs = []
    for t in raw_troughs:
        left_peaks = [p for p in raw_peaks if p['idx'] < t['idx']]
        right_peaks = [p for p in raw_peaks if p['idx'] > t['idx']]
        nearest_peak_price = None
        if left_peaks:
            nearest_peak_price = left_peaks[-1]['price']
        if right_peaks:
            rp = right_peaks[0]['price']
            if nearest_peak_price is None or rp < nearest_peak_price:
                nearest_peak_price = rp
        if nearest_peak_price and (nearest_peak_price - t['price']) / nearest_peak_price >= prominence:
            troughs.append(t)
    
    return peaks, troughs
```

#### 第3步：深谷分隔法配对

**问题**：简单取最后两个峰（`peaks[-2:]`）会有隐患。

例如：左顶A → 小回调 → 小反弹B → 深回调 → 右顶C
此时peaks里会有A、B、C三个峰，取B和C做双顶就错了。

**解决方案**：采用"深谷分隔法"——先找到显著回调谷，然后在谷的两侧寻找有效峰。

```python
def find_double_top_by_deep_trough(peaks, troughs, config):
    """
    深谷分隔法：从后向前遍历深谷，在谷两侧找峰配对
    
    关键设计：
    - 左顶：谷前60天窗口内的最高峰
    - 右顶：谷后60天窗口内的最高峰
    - 从后向前遍历，优先找最近的深谷（最新形态）
    """
    for trough in reversed(troughs):
        # === 按需动态计算 retrace_pct ===
        # retrace_pct 是深谷分隔法的概念，不是峰谷检测的输出。
        # 对每个谷，用该谷左侧 window 内的最高峰作为参照计算回调幅度。
        # 好处：解耦峰谷检测和深谷筛选，避免循环依赖。
        left_peak_candidate = find_highest_peak_before(
            peaks, trough['idx'], config.peak_window_days
        )
        if not left_peak_candidate:
            continue
        trough['retrace_pct'] = (
            (left_peak_candidate['price'] - trough['price'])
            / left_peak_candidate['price']
        )
        # 检查回调幅度是否达标
        if trough['retrace_pct'] < config.double_top.min_retracement:
            continue
        
        # 在谷前窗口内找最高峰（左顶）
        left_peak = find_highest_peak_before(
            peaks, trough['idx'], config.peak_window_days
        )
        # 在谷后窗口内找最高峰（右顶）
        right_peak = find_highest_peak_after(
            peaks, trough['idx'], config.peak_window_days
        )
        
        if not (left_peak and right_peak):
            continue
        
        # 验证左顶的上升背景（右顶不验！）
        if not has_uptrend_background(left_peak):
            continue
        
        # 验证两顶价格相近
        price_diff = abs(right_peak['price'] - left_peak['price']) / left_peak['price']
        if price_diff > config.double_top.max_price_diff:
            continue
        
        # 验证两顶间隔 ≥ 15天
        days_between = (right_peak['date'] - left_peak['date']).days
        if days_between < config.double_top.min_days_between:
            continue
        
        return {
            'pattern': 'double_top',
            'left_peak': left_peak,
            'right_peak': right_peak,
            'trough': trough,
            'neckline': trough['price']
        }
    
    return None
```

**配对逻辑**：
- 从后向前遍历深谷（优先最新的形态）
- 找到该谷前60天窗口内的最高峰（左顶）
- 找到该谷后60天窗口内的最高峰（右顶）
- 验证左顶上升背景（右顶不验）
- 验证两顶价格相近（≤3%）
- 若当前谷不满足，继续向前找更早的谷

这样即便有A→小反弹B→深谷→右顶C的嵌套结构，也会正确配对A和C（通过深谷分隔），而不是B和C。

#### 第4步：左顶/右顶取"窗口内最高峰"

右顶应取谷后60天时间窗口内的**最高峰**，而非"最近的峰"。

| 方案 | 说明 | 优缺点 |
|------|------|--------|
| 通常方案：谷后最近峰 | 取深谷后的第一个局部高点 | ❌ 可能匹配到小反弹，而非真正的右顶 |
| **新方案：谷后最高峰** | 在60天窗口内取最高点 | ✅ 更符合双重顶的定义（两个"顶"都是显著高点） |

实战中可能出现：深谷 → 小反弹 → 再回调 → 真右顶。如果严格取"谷后第一个峰"，可能匹配到中间的小反弹，而非真正的右顶。

**对称设计**：
- **左顶**：谷前60天窗口内取最高峰
- **右顶**：谷后60天窗口内取最高峰

60天窗口的意义：偏紧减少误报，偏松捕获更多形态。建议做成可配置参数 `peak_window_days`。

```python
def find_highest_peak_before(peaks, trough_idx, lookback_days=60):
    """谷前窗口内取最高峰"""
    candidates = [p for p in peaks 
                  if p['idx'] < trough_idx
                  and (trough_idx - p['idx']) <= lookback_days]
    return max(candidates, key=lambda x: x['price']) if candidates else None

def find_highest_peak_after(peaks, trough_idx, lookahead_days=60):
    """谷后窗口内取最高峰"""
    candidates = [p for p in peaks 
                  if p['idx'] > trough_idx
                  and (p['idx'] - trough_idx) <= lookahead_days]
    return max(candidates, key=lambda x: x['price']) if candidates else None
```

#### 第5步：确定颈线

颈线是两个顶部之间的最低点（中间低谷）。通常取该低谷的**最低价**。

```python
def get_neckline(trough):
    """颈线 = 中间低谷的最低价"""
    return trough['price']
```

#### 第6步：判断当前状态

根据当前价格与颈线的关系，判断形态处于哪个阶段：

信号按紧迫程度分为三级：

| 级别 | 图标 | 判断条件 | 操作含义 |
|------|------|----------|----------|
| ⚠️ **形成中** | Warning | 右顶已出现，但价格 > 颈线 | 形态未确认，设价格预警 |
| 🟡 **弱确认** | Weak Confirmation | 连续3天收盘价低于颈线 | 温和跌破，高可靠性，减仓或清仓 |
| 🔴 **强确认** | Strong Confirmation | 单日收盘价跌破颈线 ≥ 3% | 反转确认，机构出货，立即卖出/清仓 |

隐性状态（不展示为信号级别，内部处理）：

| 状态 | 触发条件 | 行为 |
|------|----------|------|
| **形态失败** | 价格突破右顶创出新高 | 清除信号 |
| **信号降级** | 确认后8周无新低 | 信号降级（强确认→弱确认→观察中） |
| **观察中** | 价格回升至颈线上方但未突破右顶 | 信号仍存在但不活跃 |

**两者关系：取"或"——任一满足即确认。** 但权重不同：
- 单日跌破3% → 立即卖出（强信号，`confirm_mode: "strong"`）
- 连续3天低于颈线 → 可减仓或清仓（弱信号但高可靠性，`confirm_mode: "weak"`）

```python
def judge_confirmation(close_series, neckline, break_pct=0.03, consecutive_days=3):
    """
    判断确认模式：强确认 / 弱确认 / 未确认
    
    Args:
        close_series: 最近几天的收盘价序列
        neckline: 颈线价格
        break_pct: 单日跌破阈值（0.03 = 3%）
        consecutive_days: 连续低于颈线的天数
    
    Returns:
        (confirmed: bool, mode: str)  # mode: "strong" / "weak" / ""
    """
    current_close = close_series.iloc[-1]
    
    # 强确认：单日收盘跌破颈线 ≥ 3%
    if current_close <= neckline * (1 - break_pct):
        return True, "strong"
    
    # 弱确认：连续N天收盘价低于颈线
    if len(close_series) >= consecutive_days:
        last_n = close_series.iloc[-consecutive_days:]
        if all(last_n < neckline):
            return True, "weak"
    
    return False, ""
```

### 2.4 信号持久化

信号持久化采用**纯函数式**实现：每次查询时基于历史数据动态推算信号状态，不依赖数据库持久存储。

规则：

- 形态确认后，信号应锚定在触发日
- 后续价格回升只是"形态可能失败"，不是"信号从未存在"
- 确认后 **8 周（56 天）** 内保持信号有效
- 如果价格突破右顶创新高 → 信号清除（形态失败）
- 如果8周后价格仍无新低 → 信号降级（从 strong_sell 降为 moderate）

实现方式：所有判断通过 `as_of_date` 参数控制截止日，引擎在内存中重放历史数据完成检测，无需写入数据库。

### 2.5 边界情况处理

| 场景 | 处理方式 |
|------|----------|
| 数据不足 | 少于60天数据，返回"数据不足" |
| 只有一个高点 | 返回"未形成双重顶" |
| 多个高点嵌套 | 深谷分隔法自动处理 |
| 价格在颈线附近震荡 | 连续3天收盘价低于颈线才确认 |
| 右顶比左顶高很多 | 价格差异>3%，视为上升延续，非双顶 |
| 左顶无上升背景 | 过滤——下跌途中的反弹不算顶 |

## 3. 三重顶（Triple Top）

### 3.1 定义与特征

三重顶是双重顶的扩展，由三个大致相同高度的顶部和两个中间低谷组成，显示多方三次冲击阻力失败，卖压极重。出现频率较低，但可靠性很高。

| 特征 | 量化规则 | 说明 |
|------|----------|------|
| 三个顶部 | 三个高点价格差异 ≤ 5% | 比双重顶放宽，因为三个顶更难完美等高 |
| 顶部间隔 | 每两个顶之间至少间隔15个交易日 | 避免短期波动 |
| 深谷数量 | 2个，各回调幅度 ≥ 6%（可配置） | 双重顶8%，三重顶可略宽松 |
| 深谷间距 | 两个深谷之间间隔 ≥ 15天 | 避免取到相邻的两个小回调谷 |
| 颈线 | 两个深谷的**最高价** | 取高值，确认更敏感；必须两个谷的支撑全部失效才确认 |
| 跌破颈线 | 同双重顶（单日3%或连续3日） | - |

**为什么三重顶的价格差异可以放宽到5%？**

三个顶比两个顶更难完美等高。实际行情中，三个顶的高度可能略有差异（比如中间顶略高），但只要差异不超过5%，仍然可以认为是有效的三重顶。

### 3.2 检测流程

从后向前找**两个有效深谷**，验证它们之间和两侧是否形成三个相近高度的峰。

**重要**：三重顶的上升背景同样只验左顶，中顶和右顶不验（与双重顶同理）。

```python
def find_triple_top(peaks, troughs, config):
    """
    检测三重顶：两个深谷，三个峰
    
    从后向前遍历深谷，找到最近的两个有效深谷
    """
    valid_troughs = []
    for trough in reversed(troughs):
        if trough['retrace_pct'] >= config.triple_top.min_retracement:
            valid_troughs.append(trough)
            if len(valid_troughs) >= 2:
                break
    
    if len(valid_troughs) < 2:
        return None
    
    # valid_troughs 是从后向前收集的，所以 [0]=右谷(较近)，[1]=左谷(较远)
    trough_right = valid_troughs[0]  # 右谷
    trough_left = valid_troughs[1]   # 左谷
    
    # 验证两谷间距 ≥ 15天
    gap_days = (trough_right['date'] - trough_left['date']).days
    if gap_days < 15:
        return None  # 谷间距不足，可能是相邻的两个小回调
    
    # 找三个峰
    left_peak = find_highest_peak_before(
        peaks, trough_left['idx'], config.peak_window_days
    )
    middle_peak = find_highest_peak_between(
        peaks, trough_left['idx'], trough_right['idx']
    )
    right_peak = find_highest_peak_after(
        peaks, trough_right['idx'], config.peak_window_days
    )
    
    if not (left_peak and middle_peak and right_peak):
        return None
    
    # 验证左顶的上升背景（中顶、右顶不验）
    if not has_uptrend_background(left_peak):
        return None
    
    # 验证三个峰价格相近
    peaks_prices = [left_peak['price'], middle_peak['price'], right_peak['price']]
    max_price = max(peaks_prices)
    min_price = min(peaks_prices)
    price_diff = (max_price - min_price) / max_price
    
    if price_diff > config.triple_top.max_price_diff:
        return None
    
    # 颈线 = 两个深谷的最高价
    # 修正（2026-05-18）：取两个深谷的最高价而非最低价。
    # 理由：较低谷之前必定先经过较高谷。取最高价意味着较高谷的支撑一旦失效
    # 形态即确认，确认更敏感；也更符合三重顶"卖压极重"的含义。
    neckline = max(trough_left['price'], trough_right['price'])
    
    return {
        'pattern': 'triple_top',
        'left_peak': left_peak,
        'middle_peak': middle_peak,
        'right_peak': right_peak,
        'trough_left': trough_left,
        'trough_right': trough_right,
        'neckline': neckline
    }
```

### 3.3 双重顶与三重顶的关系

三重顶可以看作是双重顶的扩展。在实际检测中，采用以下策略：

1. 先检测三重顶（更严格，需要三个峰和两个谷）
2. 如果不满足，再检测双重顶（只需要两个峰和一个谷）

这样设计的好处是：如果一个形态同时满足双重顶和三重顶的条件，会被归类为三重顶（更可靠的信号）。

## 4. 完整检测流程

```
输入：日线数据
    │
    ▼
第1步：数据检查（至少60天数据）
    ├── 不满足 → 返回"数据不足"
    └── 满足 ↓
    │
第2步：识别局部高点、低点（窗口5天，突出度≥3%）
    │
    ▼
第3步：检测三重顶
    ├── 找到两个有效深谷 → 三个峰 → 左顶验上升背景
    │   ├── 左顶无上升背景 → 跳过
    │   ├── 三顶价差>5% → 跳过
    │   └── 满足 → 返回三重顶结果
    └── 未找到 ↓
    │
第4步：检测双重顶（深谷分隔法，从后向前）
    ├── 找到有效深谷 → 左右顶 → 左顶验上升背景
    │   ├── 左顶无上升背景 → 继续向前找更早的谷
    │   ├── 两顶价差>3% → 继续向前找
    │   └── 满足 → 返回双重顶结果
    └── 未找到 → 返回"无有效头部形态"
    │
第5步：确定颈线（深谷最低价）
    │
    ▼
第6步：判断状态
    ├── 价格 > 颈线 → "正在形成"（warning）
    ├── 单日跌破3% → "强确认"（confirmed, strong_sell）
    ├── 连续3日低于颈线 → "弱确认"（confirmed, moderate_sell）
    ├── 价格突破右顶 → "形态失败"（清除信号）
    └── 其他 → "观察中"
```

### 万华化学 600309 @ 2023-09-27

这是一个经典的A股双重顶案例，经过4轮上升背景条件迭代最终正确识别。

**K线走势**：
```

2023-06-01: 76.22（阶段性低点）
2023-07-31: 95.92（左顶 ✅）
2023-08-25: 87.29（深谷/颈线）
```

**各峰的上升背景检查**：

| 峰 | 日期 | 60天low→high | MA50方向 | 背景 | 判定 |
|---|---|---|---|---|---|
| 反弹峰 | 23-04-18 @ 92.85 | 8.3%（不满足） | 向下 | ❌ | 正确过滤（下跌反弹） |
| 左顶 | 23-07-31 @ 95.92 | 22.4%（≥20%✅） | 向上 | ✅ | 正确识别为左顶 |

- 左顶：2023-07-31 @ 95.92
- 右顶：2023-09-04 @ 95.27
- 颈线：87.29
- 两顶价差：0.68%（≤3%✅）
- 深谷回调：(95.92 - 87.29) / 95.92 = 9.0%（≥8%✅）

**后续走势验证**：
- 2023-10月起持续下跌，至2024年初跌至约70元
- 双重顶信号有效预警了约20%的跌幅

## 8. 与头肩顶的关系

| 特征 | 双重顶 | 三重顶 | 头肩顶 |
|------|--------|--------|--------|
| 高点数量 | 2个 | 3个 | 3个（左肩、头、右肩） |
| 头部高度 | 两顶相近 | 三顶相近 | 头部明显高于两肩 |
| 颈线 | 水平 | 水平 | 可倾斜 |
| 上升背景 | 仅左顶验 | 仅左顶验 | 仅左肩验 |

| 复杂度 | 简单 | 中等 | 较复杂 |
| 可靠性 | 较高 | 很高 | 最高 |

**检测顺序建议**：头肩顶 → 三重顶 → 双重顶

这样设计的好处是：
- 最可靠的形态优先检测
- 避免一个形态被错误归类为另一种
- 三重顶可视为双重顶的扩展，双重顶可视为头肩顶的特例

### 2026-04-12：上升背景检查4轮修正

| 轮次 | 问题 | 修正 |
|------|------|------|
| V1 | 背景检查只验整体，不验每个顶 | 改为只验左顶 |
| V2 | MA200太宽松，下跌反弹峰也能通过 | 去掉MA200，改用MA50 |
| V3 | 全数据集max/min涨幅误算（高点在低点之前） | 新增方向性验证：high_pos > low_pos |
| V4（最终） | 涨幅阈值30%对大盘股过严 | 降至20%，MA50回溯10天 |

**核心教训**：
1. **涨幅计算必须验证方向**：max/min的比值 ≠ 涨幅，高点必须在低点之后
2. **MA周期越短越灵敏**：MA50比MA200更能反映真实趋势方向，下跌反弹时MA50通常已向下
3. **左顶验背景、右顶不验**：右顶本身就是回调后反弹，这是双重顶的定义特征
4. **用盘中范围（low→high）而非收盘价**：顶部常有长上影线，收盘价会低估实际波动幅度
5. **20%涨幅阈值更适合A股**：30%对大盘股过于苛刻

### 改造内容

峰谷识别从 `find_peaks_troughs(window, prominence)` 窗口扫描法改为缠论 bi（笔）结构。
