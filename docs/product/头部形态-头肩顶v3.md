# 头部与失败形态

## 定义

常见的见顶反转形态：**头肩顶、双重顶（M头）、三重顶**等经典形态都适用于欧奈尔体系。出现这些形态时，意味着上升趋势可能逆转。

**失败形态的卖出信号**：特指欧奈尔体系中的买入形态（如杯柄、双重底、口袋支点等）在突破后未能延续上涨，反而迅速回落至突破点以下的情形。这两类信号都是重要的卖出依据，识别它们可以帮助投资者在趋势逆转前锁定利润、规避风险。

## 头部形态（Top Formations）

### 头肩顶（Head and Shoulders Top）

#### 定义与特征
  
头肩顶是技术分析中最可靠的顶部反转形态之一，由左肩、头部、右肩以及颈线构成。它反映了买方力量从强到弱、卖方力量逐渐主导的全过程。

"本检测引擎支持日线(freq='D')和周线(freq='W')两种周期，周线形态的可靠性更高，参数阈值略有差异。

#### 形态确认条件汇总（欧奈尔量化规则）

```text
✓ 上升背景（左肩前60天从低点上涨 ≥20% 或 MA50曾向上）
✓ 头部高点 > 左肩高点 × 1.03
✓ 头部高点 > 右肩高点 × 1.03（即右肩 < 头部 × 0.97）
✓ 右肩成交量 < 左肩成交量 × 0.8（左肩/右肩各取前后5天区间均量对比，反映买盘衰竭）
✓ 收盘价跌破颈线 ≥3%（颈线取头部回调低点，即两个谷中较高者）
```
> 附加筛选：左右肩价差 ≤ 5%（可配置放宽至 8-10%）。三峰价差在 3%-5% 模糊地带 → 归三重顶。

#### 关键要素标注

| 组成部分 | 特征 | 量化规则 |
|----------|------|----------|
| **左肩** | 股价经历一波上涨后出现回调，形成第一个高点。成交量通常较大。 | 从前期低点上涨至少20%，回调幅度10%， |
| **头部** | 股价再次上涨并创出新高（高于左肩），随后大幅回调至接近左肩低点。成交量可能较左肩略有萎缩。 | 头部高点比左肩高点高3%以上；从头部高点回调至颈线的幅度≥左肩回调幅度 |
| **右肩** | 股价第三次上涨，但无法超越头部高点，形成第二个高点（低于头部）。成交量明显萎缩。 | 右肩高点 < 头部高点 × 0.97（即低于3%以上）；右肩成交量 < 左肩成交量的80% |
| **颈线** | 水平线，取头部回调低点（两个谷中较高者）。与三重顶"取最高价"原则一致。 | 头部回调低点作为颈线基准价 |
| **跌破颈线** | 股价收盘价跌破颈线。 | 收盘价低于颈线3%以上（强确认），或连续3日低于颈线（弱确认） |
| **成交量** | 右肩形成期成交量相比左肩明显萎缩。 | 左肩/右肩各取前后5天区间均量对比，右肩均量 < 左肩均量 × 0.8 |

**量化识别代码框架**：
```python
def is_head_shoulders_top(weekly_df):
    # 需要识别最近三个波峰和两个波谷
    peaks = find_peaks(weekly_df['high'], min_distance=5)  # 找局部高点
    troughs = find_troughs(weekly_df['low'], min_distance=5) # 找局部低点
    if len(peaks) < 3 or len(troughs) < 2:
        return False
    left_shoulder, head, right_shoulder = peaks[-3], peaks[-2], peaks[-1]
    neckline1, neckline2 = troughs[-2], troughs[-1]
    # 条件1：头部最高
    if head['price'] <= left_shoulder['price'] or head['price'] <= right_shoulder['price']:
        return False
    # 条件2：右肩低于左肩（可选，标准形态要求右肩略低）
    if right_shoulder['price'] > left_shoulder['price']:
        return False
    # 条件3：右肩成交量萎缩
    if right_shoulder['volume'] > left_shoulder['volume'] * 0.8:
        return False
    # 条件4：当前价格跌破颈线（以最近两个低点连线为准）
    neckline_price = (neckline1['price'] + neckline2['price']) / 2  # 简化
    if weekly_df['close'].iloc[-1] < neckline_price * 0.97:
        return True
    return False
```

#### 常见疑问

##### 问题1：左肩和右肩之间需要价差约束吗？

- A方案：左肩 ≈ 右肩（价差 ≤ 5%），头部显著高于两者（≥3%）——最标准的头肩顶
- B方案：只要求头部 > 左肩 + 3%，右肩 < 头部 - 3%，左右肩不必相近——宽松版

- **结论**：选 **A方案（左右肩相近）**，但建议将“左右肩价差约束”设为 **≤ 8%**（而非5%），或者干脆**不强制价差约束，改为高度相对约束**。
- **深度理由**：
    - **形态本质**：头肩顶本质是“多空力量三次博弈后，多方衰竭”。**右肩<左肩**本身已说明多方力量比第一波弱了。如果右肩显著低于左肩（比如左肩100，右肩80），那这波反弹太弱，形态更像**下跌中继平台**或**不规则顶**，而非经典头肩顶。
    - **B方案的隐患**：头110、左100、右95，虽然头最高，但左肩和右肩落差大，往往预示着趋势已经走坏，反弹无力。报为头肩顶会让卖点滞后（跌破颈线时已跌很深）。
    - **工程化建议**：使用 **`max(左肩, 右肩) / min(左肩, 右肩) - 1 <= 0.05`** 作为“左右肩对称性”的辅助筛选条件。

##### 问题2： 颈线：水平线还是斜线？

- A方案：水平颈线 = 两个谷底最低价的平均值（简单，与双/三重顶一致）
- B方案：倾斜颈线 = 两谷底连线延伸（经典头肩顶定义）

- **结论**：**V1.0 必选 A方案（水平颈线）**。V2.0 再考虑斜线。
- **具体实现逻辑**：
    - **水平颈线计算**：取头部回调低点 `Trough_Head` 作为颈线基准价（即两个谷中的较高者，与三重顶"取最高价"原则一致）。因为头肩顶的确认信号是**跌破头部回调低点**。左肩的低点仅作为辅助确认形态对称性。
    - **为什么先不做斜线**：倾斜颈线的斜率计算在噪声较大的日线数据中极难标准化（是连接影线低点还是实体低点？斜率超过多少度无效？）。**先做水平颈线，已经能抓住90%的有效头肩顶形态。**

##### 问题3：深谷分隔法是否适用？

头肩顶有3个峰（左肩/头/右肩）和2个谷（颈线），结构比双/三重顶更固定。有两种检测思路：

- A方案：沿用深谷分隔法——从后向前找2个有效深谷，取谷前最高峰(左肩)、谷间最高峰(头部)、谷后最高峰(右肩)
- B方案：3峰序列法——直接找最近的3个峰+2个谷，按时间排序验证

- **结论**：**完全复用双重顶逻辑**。
- **操作细则**：仅在检测到**左肩**时，向前回溯60天验证上涨背景。一旦左肩通过背景验证，该形态区间的后续部分（头、右肩）**自动豁免背景检查**。

### 问题4：检测算法选择（选A，深谷分隔法增强版）

- **结论**：**坚决选 A方案（深谷分隔法）**。
- **深度理由**：如果直接找3个峰（B方案），在震荡行情中你会找出无数个“假峰”，导致计算量爆炸且误报率极高。**必须先利用“显著回调（深谷）”来框定有效区间。**
- **头肩顶版“深谷分隔法”三步走**：
    假设当前日期为 T（指定日），我们在 df[0:T] 的历史区间内执行检测：

  1. 从 T 向前（向左）扫描，找到最近的两个"有效深谷"。
   定义：回调幅度 > 10%，或价格跌破 MA20 后形成的局部低点。
   
  2. 确定三个峰的位置：
   - 取两个深谷之间的最高点 → 头部
   - 取第一个深谷之前的最高点 → 左肩
   - 取第二个深谷之后、T之前的最高点 → 右肩
   
  3. 验证高度关系：
   头部 > 左肩 × 1.03  且  头部 > 右肩 × 1.03  且  右肩 ≤ 左肩 × 1.05。

**图解（时间轴从左→右，左侧为历史，右侧为当前）**

   K线时间轴： 历史 ←────────────────────── 当前(T)
           │                              │
           ▼                              ▼
        左肩形成期   头部形成期   右肩形成期   (T=指定日)
        [  左肩 ]   [  头部  ]   [ 右肩 ]
           /‾\        /‾‾‾\       /‾\
          /   \      /     \     /   \
         /     \____/       \___/     \________
             谷1           谷2                颈线
             ↑             ↑
           有效深谷1      有效深谷2
           (回调>10%)     (回调>10%)

##### 问题5：是否要在头肩顶加入成交量萎缩条件

- **结论**：**必须加入**。这是区分“真头肩顶”和“高位强震仓洗盘”的关键。头部形态向下突破时，是不需要成交量放大配合的。反而缩量更可怕。
- **数据来源**：直接从数据库取 `volume` 聚合到对应高点日。
- **量化标准**：**右肩最大成交量日(或右肩形成区间的均量) < 左肩最大成交量日(或左肩区间均量) * 0.8**。
- **若不满足**：只报“疑似头肩顶”或降级为“复杂头部”。
- **成交量**：取左肩/右肩**前后5天区间的均量**对比

##### 问题6：是和双重顶/三重顶放在同一个引擎还是独立引擎

- **结论**：**明确扩展现有双重顶/三重顶引擎 `top_pattern_engine`）**。
- **反驳独立引擎的理由**：
    1. **基础原子能力完全一样**：找峰、找谷、算回调幅度、验证背景。重复写两套代码是巨大的维护灾难（比如以后优化找峰算法要改两个文件）。
    2. **避免优先级冲突混乱**：如果两个引擎独立运行，都返回结果，最后谁说了算？合并引擎可以用**策略模式/责任链模式**清晰定义检测顺序。
- **架构设计建议**：
    ```python
    class TopPatternEngine:
        def detect(self, df):
            # 1. 统一数据预处理（找峰谷）
            # 2. 按优先级调用检测器
            patterns = []
            hs = self._check_head_shoulders(df) # 内部复用峰谷数据
            if hs:
                patterns.append(hs)
            else:
                # 只有不是头肩顶才去检测三重顶/双重顶
                patterns.append(self._check_triple_top(df))
            return patterns
    ```

##### 问题7：如果3个峰同时满足头肩顶和三重顶条件，检测优先级与互斥处理

- **结论**：**头肩顶 > 三重顶 > 双重顶**。
- **冲突解决规则**：
    - **规则1（头部唯一性）**：如果三个峰中，**中间的峰**比左右两个峰**都高出 3% 以上** —— **强制归类为头肩顶**（无论左右肩是否完全等高）。这是不可辩驳的形态特征。
    - **规则2（价差模糊区）**：如果三个峰两两价差都在 **3%-5%** 之间（处于头肩顶和三重顶的模糊地带）：
        - 优先检查**量能**：右肩缩量严重（<80%） -> **头肩顶**。
        - 其次看**时间间隔**：头部到右肩回调更深更急 -> **头肩顶**。
        - 否则 -> **三重顶**。

##### 问题8：头肩顶是基于日K线还是周K线检测

在欧奈尔CAN SLIM体系中，**周线图是识别基底形态的主战场**，日线图主要用于寻找精确买点（如口袋支点）。

- **结论**：必须支持周线，但优先实现日线

| 维度 | 日线 | 周线 | 结论 |
|------|------|------|------|
| **数据可得性** | 极高（所有API默认提供） | 需要聚合转换 | 日线优先 |
| **形态数量** | 噪音多，假形态多 | 形态更标准、更可靠 | 周线更优 |
| **欧奈尔原教旨** | 辅助工具 | **主要工具** | 必须支持 |
| **A股实战** | 适合右侧确认卖出 | 适合左侧预警 | 两者互补 |

**决策**：引擎必须支持 `freq` 参数（`'D'` 日线 / `'W'` 周线），通过数据入口处重采样统一后续检测逻辑。配置采用独立块方案（`head_shoulders_daily` / `head_shoulders_weekly`），参数各自独立可调。

- **配置独立块结构**：
```yaml
head_shoulders:
  daily: { enabled: true, min_retracement: 0.10, ... }
  weekly: { enabled: true, min_retracement: 0.12, min_distance: 2, ... }
```

- **实现方案**：周期重采样层

不需要为周线单独写一套引擎，只需在数据输入前加一层**重采样**：

```python
def prepare_ohlc(df, freq='D'):
    """将日线数据转换为目标周期"""
    if freq == 'D':
        return df
    elif freq == 'W':
        return df.resample('W-FRI').agg({
            'open': 'first',
            'high': 'max',
            'close': 'last',
            'low': 'min',
            'volume': 'sum'
        }).dropna()
```

**引擎内部所有逻辑（找峰谷、深谷分隔、成交量比较）完全不改**，只操作传入的DataFrame。这样：
  - 日线验证：`engine.detect(df, freq='D')`
  - 周线验证：`engine.detect(df, freq='W')`

- **参数微调对照表（周线 vs 日线）**

由于周线一根K线代表5个交易日，部分阈值需要等比缩放：

| 参数 | 日线值 | 周线建议值 | 调整理由 |
|------|--------|------------|----------|
| `min_distance` (峰谷最小间隔) | 5 | **2** | 周线2根≈10个交易日，形态更紧凑 |
| `min_depth_pct` (深谷幅度) | 10% | **12%~15%** | 周线回调需更深才能算有效谷 |
| `lookback_days` (背景检测窗口) | 60天 | **12周** | 60个交易日≈12周 |
| `volume_shrink_ratio` | 0.8 | **0.7** | 周线量能萎缩信号更严格 |
| `neckline_break_pct` | 3% | **2%** | 周线收盘跌破2%已足够确认 |

### 补充讨论 (2026-05-18) — grill-with-docs 对齐决策

| 决策项 | 结论 | 理由 |
|--------|------|------|
| 颈线取值 | 头部回调低点（两个谷中较高者） | 与三重顶"取最高价"规则一致 |
| 成交量萎缩 | 左肩/右肩各取前后5天区间均量对比，右肩 < 左肩 × 0.8 | V1.0 仅用缩小量判断 |

| 优先级分流 | 严格"头 > 两肩 × 1.03"；模糊地带自然归三重顶 | 无需额外处理 |

| freq 参数 | 日/周线都支持，独立配置块 | V1.0 日线 → Phase 2 周线 |
| 配置结构 | `head_shoulders: { daily: {...}, weekly: {...} }` | 独立块方案 A |
| 引擎合并 | 扩展现有 `top_pattern.py`，启用 `hs_enabled` | 共享峰谷检测等基础设施 |

- 为什么周线头肩顶对A股尤其重要？

A股存在显著的**周线效应**：
- 日线头肩顶容易在震荡市中被**骗线**（右肩放量假突破后回落）。
- 周线头肩顶一旦形成，下跌空间和时间都远大于日线形态（如贵州茅台2021年周线头肩顶后跌了3年）。
- 机构资金调仓周期以周为单位，周线形态更能反映主力意图。

- **开发顺序**：
   - Phase 1：跑通日线检测，用宁德时代、东方财富案例验证
   - Phase 2：加入 `freq` 参数和周线重采样逻辑，用贵州茅台周线案例验证
   - Phase 3：根据验证结果微调周线阈值表

## 缠论化改造 (2026-06-09)

### 改造内容

峰谷识别从 `find_peaks_troughs(window, prominence)` 窗口扫描法改为缠论 bi（笔）结构。

### 改造方式

- `detect()` 优先调用 `chanlun_structure.get_bi_peaks()` / `get_bi_troughs()` 获取峰谷
- 笔顶（direction='向上'的 edt+high）= 峰，笔底（direction='向下'的 edt+low）= 谷
- 无缠论数据或无 stock_code 时自动降级回窗口法
- 头肩顶/双重顶/三重顶的检测逻辑（成交量对比、颈线判断、确认分级）保持不变
