## 1. 产品概述

### 1.1 核心问题

在欧奈尔 CANSLIM 选出的观察池中，缠论择时是否提供额外 alpha？O'Neil 进阶精选（形态+行业共振）是否能进一步优中选优？

三个层次，逐一递进：

| 组别 | 选股逻辑 | 回答的问题 |
|------|---------|-----------|
| **全池基准** | 观察池全部股票，以当日收盘价买入 | 不挑不拣，池子本身的 alpha |
| **缠论叠加** | 池内 + 同日缠论买入信号 | 跨体系叠加，1+1 是否 > 2 |
| **O'Neil 进阶** | 池内 + O'Neil 精选（形态/行业共振） | 单体系深挖，进一步优中选优 |

### 1.2 核心原则

**每个交易日是一个独立实验**。每天欧奈尔观察池不同（RS 动量、CANSLIM 评分、信号分布每天都在变），每天选择单独评估，跨日汇总后看整体表现。同一股票在多天重复出现是正常现象——它不是 bug，是信号持续性的体现。

## 2. 回测方法论

### 2.1 单日实验流程

对于每个回测交易日 T：

```
步骤1: 读取 T 日的欧奈尔观察池（discipline_observation_pool）
    ↓
步骤2: 对池内每只股票运行缠论分析引擎
    ├─ 检查 T 日当天是否有买入信号（精确日期匹配，signal_window=0）
    ├─ 有信号 → 计入「缠论原始」集
    ├─ 通过三步规则链 → 计入「缠论过滤后」集（⊆ 原始集）
    └─ 选最优信号类型（三买 > 二买 > 类一买 = 一买）
    ↓
步骤3: 读取 T 日的 O'Neil 精选股票（discipline_screening_daily）
    └─ 全量纳入，不设数量/分值阈值
    ↓
步骤4: 对三组分别计算：
    ├─ 全池基准：池内全部股票，T 日收盘价买入
    ├─ 等额随机：从池内随机抽 N 只（N = 缠论信号数量），重复 50 次取均值
    └─ 所有组别以相同入场价（T 日收盘价）买入
    ↓
步骤5: 计算 5/10/20 个交易日的 forward return
    ↓
步骤6: 统计对比各组均收益和胜率
```

### 2.2 信号窗口

默认 `signal_window=0`（精确匹配），即仅取观察池日期当天的缠论信号。不扩展到前后 N 天，避免时间锚定错位。

### 2.3 入场价规则

三组全部以**观察池日期的收盘价**作为入场价。理由：信号在当日收盘后才能确认，实际交易只能在次日开盘执行，但收盘价是当日最合理的价格锚点。若某股票当日无收盘价（停牌），则从该组中移除。

### 2.4 持有期

5 个交易日 / 10 个交易日 / 20 个交易日。数据不足时标记为 null（不参与统计）。

## 3. 对照组设计

### 3.1 全池基准

买入当日观察池中全部股票。回答："加入缠论筛选后，是否跑赢了全池买入？"

### 3.2 等额随机采样

每天缠论组有 N 只股票，从全池中随机抽 N 只，重复 50 次取均值。回答："同样选 N 只的情况下，缠论选得更好吗？"

等额随机采样仅在对比「缠论组 vs 随机」场景使用，O'Neil 进阶组有自己独立的等额随机对照。

### 3.3 O'Neil 进阶组

每天从 `discipline_screening_daily` 表读取当日精选股票，全量纳入，不设数量或分值阈值。与缠论组不互斥——某股票可能同时出现在两组中。

---

## 4. 过滤条件：三步规则链

### 4.1 三步规则

| 步骤 | 条件 | 通过标准 | 未通过处理 |
|:--:|------|---------|----------|
| Step 1 结构过滤 | 走势类型 | 为「上涨趋势」或「盘整」 | 阻挡 |
| Step 2 信号匹配 | 买入信号 | 窗口内有至少一个买入信号 | 已在窗口筛选中保证 |
| Step 3 历史校验 | 背驰后追踪 | 该股历史上「反趋势」占比 ≥ 30% | 阻挡 |

### 4.2 过滤后/原始关系

**同一次运行同时产出两份文件**。过滤后 ⊆ 原始（过滤后是原始的子集）。不存在不同运行数据的交叉污染。

---

## 5. 市场切片维度

每个交易日附带 4 类市场上下文标签，用于分组汇总：

| 维度 | 取值 | 数据来源 |
|------|------|---------|
| O'Neil 大盘状态 | 确认上涨 / 反弹尝试 / 压力上涨 / 调整 | `distribution_day` + `follow_through_day` 引擎 |
| NH-NL 市场广度 | 广度健康 / 广度分化 / 广度恶化 | `index_daily_kline` 表 |
| 均线趋势 | 多头排列 / 震荡 / 空头排列 | 主要指数相对 20/50 日均线位置 |
| 最强指数 RS | 动量强劲(≥80) / 动量温和(40~80) / 动量疲弱(<40) | `strongest_index` 引擎 |

数据缺失时标记为 null，该日在该切片维度下不参与统计。

## 8. 运行方式

### 8.1 日常运行

在 `daily_update.py` 中新增步骤，每天收盘后自动运行当天回测：

```bash
python src/scanners/chanlun_backtest_compare.py --date 2026-06-03 --filter
```

### 8.2 历史回填

首批回填最近 2 周（约 10 个交易日）。后续自然累积。

```bash
# 循环回填
for d in 2026-05-21 2026-05-22 ... 2026-06-02; do
  python src/scanners/chanlun_backtest_compare.py --date $d --filter
done
```

### 8.3 汇总计算

前端实时计算（方案 A）。加载所有单日 JSON 后在浏览器中汇总。数据量不超过 100 个交易日时无需预计算。

## 9. 非目标（明确排除）

- 不模拟真实持仓管理（无仓位、无止损、无加仓）
- 不扩展信号窗口（signal_window=0，精确日期匹配）
- 不做统计显著性检验（t-test 等留到后续版）
- 不引入多周期缠论信号（日线级别仅用日线）
- O'Neil 进阶组不做阈值筛选（全量纳入）

---

## 10. 设计原则

1. **每个信号都是独立样本**：同股异日 ≠ 重复，是不同市场条件下的独立事件
2. **等额对比控制规模效应**：缠论 N 只 vs 随机抽 N 只，消除样本量差异
3. **市场切片回答"什么时候好用"**：不只汇报整体，也要汇报分段表现
4. **数据原子性**：同一轮运行产出原始+过滤后双文件，杜绝跨运行交叉污染
5. **可追溯**：每条信号有明细，每个统计有 N 值，每天有市场上下文
6. **不粉饰**：结果怎么跑出来的就怎么展示，不选择性呈现，不美化
