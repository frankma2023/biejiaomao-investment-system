# 卖出信号引擎缠论化重构 · 产品需求书

> 版本：v1.0 | 日期：2026-06-09 | 状态：PRD 草案  
> 参考 PRD：`MW信号识别引擎_产品需求书.md` `头部形态-头肩顶v3.md` `头部形态-两重顶和三重顶v3.md` `见顶信号--高潮见顶v3.md` `见顶信号-铁轨线v3.md` `缠论分析引擎_产品需求书.md`

---

## 1. 问题诊断

### 1.1 现状

系统共有 4 个卖出信号引擎，全部采用**固定窗口峰谷扫描**：
- `top_pattern.py`：头肩顶 / 双重顶 / 三重顶
- `climax_top.py`：高潮见顶
- `railroad_tracks.py`：铁轨线
- （抛盘日检测不涉及个股峰谷，不在此列）

核心算法是 `find_peaks_troughs(window, prominence)`——用固定窗口大小和固定显著度阈值扫描价格序列找局部高低点。

### 1.2 根因分析

| 问题 | 原因 |
|------|------|
| 同一套参数套所有股票 | 波动大的小票和波动小的蓝筹用同一个 `window=5, prominence=0.03` |
| 峰谷识别不稳定 | 日线级别的噪音峰/噪音谷会被误判为形态点 |
| 左右肩边界模糊 | "左肩前 5 天""右肩后 5 天"等硬编码窗口经常把真正的肩切歪 |
| 与买入引擎割裂 | MW 信号、基部突破、口袋支点已用缠论 bi 精确定位，卖出引擎还在自己猜 |

用户反馈："准确性很差"。

### 1.3 对比：买入引擎为什么准

| 买入引擎 | 峰谷来源 | 精度 |
|------|------|------|
| MW 信号 | 缠论笔顶/笔底（`bi_list`，`direction='向下'`的`sdt`为笔顶） | H/L 精确到日 |
| 基部突破 V2 | 同上 | 基部下沿 = L 日最低价 |
| 口袋支点 V3 | 共用 MW 的 H/L/C 结构 | 盘整区边界精确 |
| **头肩顶（现状）** | `find_peaks_troughs(window=5)` | 经常把噪音峰当肩 |
| **双重顶（现状）** | 同上 | 两峰高度差判断不准确 |
| **高潮见顶（现状）** | 同上 | 加速段起止点模糊 |

结论：峰谷识别的精度差异，是买入引擎好于卖出引擎的根本原因。

## 2. 解决方案：统一缠论结构层

### 2.1 核心思路

不再让每个引擎各自调缠论或各自做窗口扫描。创建一个**共享结构层 `chanlun_structure.py`**，对外暴露标准化的峰谷接口。所有需要峰谷识别的引擎（买入 + 卖出）全部调用同一层。

```
                    ┌─────────────────────────┐
                    │  chanlun_structure.py    │
                    │  (共享结构层)            │
                    │  - get_bi_peaks()        │
                    │  - get_bi_troughs()      │
                    │  - get_recent_bi_list()  │
                    │  - get_segment_structure()│
                    └──────┬──────────────────┘
           ┌───────────────┼───────────────┐
    ┌──────┴──────┐ ┌──────┴──────┐ ┌──────┴──────┐
    │ 买入引擎     │ │ 卖出引擎    │ │ 卖出引擎    │
    │ MW/BO/PP    │ │ top_pattern │ │ climax_top  │
    └─────────────┘ └─────────────┘ └─────────────┘
```

### 2.2 缠论 bi 做峰谷检测的天然优势

缠论笔的定义本身就包含了峰谷识别的核心逻辑：

| 缠论笔规则 | 峰谷检测含义 |
|------|------|
| 至少 5 根 K 线构成一笔 | 自动过滤噪音峰（<5 根 K 线的毛刺不算峰） |
| 笔的端点 = 局部极值 | 笔顶 = 阶段性最高点，笔底 = 阶段性最低点 |
| 笔严格交替（上→下→上→下） | 天然区分峰和谷，不会连续两个峰或两个谷 |
| 包含关系处理 | K 线合并后找极值，比裸 K 线更稳定 |

**一个 bi 顶就是一个可靠的峰，一个 bi 底就是一个可靠的谷。** 不需要 window 参数，不需要 prominence 阈值。

### 2.3 数据来源

`chanlun_scan_daily` 表的 `bi_json` 字段已缓存全观察池股票的缠论笔数据。每日更新步骤 17 自动刷新。

```sql
SELECT stock_code, bi_json FROM chanlun_scan_daily
WHERE scan_date = (SELECT MAX(scan_date) FROM chanlun_scan_daily)
  AND stock_code = ?
```

`bi_json` 结构示例：
```json
[
  {"sdt": "2026-03-15", "sprice": 35.2, "edt": "2026-04-10", "eprice": 42.8, "direction": "向上"},
  {"sdt": "2026-04-10", "sprice": 42.8, "edt": "2026-05-08", "eprice": 28.5, "direction": "向下"},
  ...
]
```

从 `bi_json` 中提取峰谷极其简单：
- **笔顶（峰）**：`direction='向上'` 的 `edt`（终点日期）和 `eprice`（终点价格），或 `direction='向下'` 的 `sdt`（起点日期）和 `sprice`（起点价格）
- **笔底（谷）**：`direction='向下'` 的 `edt`，或 `direction='向上'` 的 `sdt`

## 3. 四个卖出引擎的缠论化方案

### 3.1 头肩顶（Head and Shoulders）

**当前**：`find_peaks_troughs(window=5)` → 取最近三个峰 → 判断是否头>左肩>右肩

**改进**：取最近 N 个 bi 顶（峰）→ 取倒序三个 → 判断形态

```
bi_peaks = get_bi_peaks(klines)  # 从chanlun_scan_daily获取
recent_3 = bi_peaks[-3:]          # 最近三个笔顶

左肩 = recent_3[0]  # 最旧的峰
头部 = recent_3[1]  # 中间的峰（必须最高）
右肩 = recent_3[2]  # 最新的峰

判断:
  头部价格 > 左肩价格 × 1.03
  头部价格 > 右肩价格 × 1.03
  右肩成交量 < 左肩成交量 × 0.8
  收盘价 < 颈线（两谷中较高者）
```

**收益**：不需要调 window 和 prominence。笔顶天然就是值得关注的峰，不会把日线毛刺当左肩。

### 3.2 双重顶（Double Top）

**当前**：`find_peaks_troughs()` → 取最近两个峰 → 判断高度相近

**改进**：取最近两个 bi 顶 → 判断

```
bi_peaks = get_bi_peaks(klines)
recent_2 = bi_peaks[-2:]

左峰 = recent_2[0]
右峰 = recent_2[1]

判断:
  |左峰价格 - 右峰价格| / 左峰价格 ≤ 5%
  中间 bi 底（谷）明确存在
  收盘价 < 颈线（谷的价格）
```

### 3.3 三重顶（Triple Top）

与双重顶同理，取最近三个 bi 顶，判断三者高度差 ≤ 5%。

### 3.4 高潮见顶（Climax Top）

**当前**：周线扫描加速上涨段 + 日线反转确认

**改进**：用 bi 的力度（涨跌幅/持续时间）判断加速

```
recent_bi = get_recent_bi_list(klines, count=10)

# 找最后一段向上加速的 bi
last_up_bi = [b for b in recent_bi if b.direction=='向上'][-1]
prior_up_bi = [b for b in recent_bi if b.direction=='向上'][-2]

# 判断加速
if last_up_bi.涨幅 > prior_up_bi.涨幅 × 1.5:
    # 加速上涨，高潮特征

# 判断反转
if recent_bi[-1].direction == '向下':
    # 最新一笔是向下的，可能已反转
```

### 3.5 铁轨线（Railroad Tracks）

铁轨线是两根特定 K 线组合（前阳后阴，收盘价接近），不依赖峰谷识别。此引擎**不需要**缠论化改造，保持现有逻辑即可。

## 4. 共享结构层 `chanlun_structure.py` 接口设计

```python
# src/scanners/chanlun_structure.py

def get_bi_list(stock_code, db=None) -> list:
    """从 chanlun_scan_daily 获取股票的笔列表"""
    
def get_bi_peaks(bi_list, count=None) -> list:
    """提取笔顶（峰），按日期排序。count限制返回最近N个"""
    
def get_bi_troughs(bi_list, count=None) -> list:
    """提取笔底（谷），按日期排序"""

def get_recent_bi(bi_list, count=10) -> list:
    """获取最近N笔"""

def get_bi_by_date_range(bi_list, start_date, end_date) -> list:
    """按日期范围过滤笔"""

def get_segments(bi_list) -> list:
    """从笔计算线段（为后续扩展留接口）"""
```

### 4.1 迁移路径

| 阶段 | 内容 |
|:--:|------|
| 1 | 创建 `chanlun_structure.py` 共享层 |
| 2 | MW 信号、基部突破 V2、口袋支点 V3 改为调用共享层（验证正确性） |
| 3 | `top_pattern.py`（头肩顶/双重顶/三重顶）改为用 bi 峰谷 |
| 4 | `climax_top.py` 改为用 bi 力度判断加速 |

## 6. 回测验证方案

| 对比维度 | 旧引擎（窗口法） | 新引擎（缠论法） |
|------|------|------|
| 信号数量 | 旧版日产量 | 新版日产量（预期更少但更准） |
| 人工抽检 | 抽查 20 个旧版信号，标记哪些是噪音 | 抽查 20 个新版信号，标记准确率 |
| 卖出后走势 | 信号后 5/10/20 日最大回撤 | 同上 |

## 7. 风险与局限

1. **bi 数据依赖**：`chanlun_scan_daily` 的 bi_json 需要每日更新（已在 daily_update 步骤 17 自动执行）
2. **bi 确认滞后**：CZSC 的笔确认有延迟（需要等反向笔走出来才能确认前一笔），可能导致顶峰识别晚 3~5 天。但这对卖出信号来说是可接受的——头部形态的右肩确认本身就发生在顶部之后
3. **铁轨线不改造**：铁轨线是单日/两日 K 线形态，不涉及峰谷，保持现状
4. **与现有买入引擎的兼容**：共享层替代 MW/BO/PP 的缠论调用后，需确保输出完全一致
