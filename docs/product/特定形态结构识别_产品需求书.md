## 1. 产品概述

### 1.1 核心问题

A股市场中存在一种反复出现的突破形态：股票经历前高后深度调整，在底部缩量横盘，随后以放量阳线首次突破（突破日1），短暂整理后再以更大成交量二次突破（突破日2），之后展开主升浪。

这个形态能否被量化描述？如果提取出足够的量化特征，未来是否可以做成每日扫描引擎，自动发现正在形成该形态的股票？

### 1.2 第一阶段目标

**不扫描，先积累。** 由人工判断形态的起止日期，录入系统后自动提取结构节点和量化特征。逐步积累案例库，分析共性特征后，再决定是否进入自动化扫描阶段。

### 1.3 形态结构

```
前高(H) → 调整段(D) → 最低点(L) → 横盘区(C) → 突破日1(B1) → 整理段(P) → 突破日2(B2) → 主升浪
```

**六个结构节点**：

| 节点 | 符号 | 定义 |
|------|:--:|------|
| 前高 | H | 调整前的局部峰值。用盘中最高价判定，代表"天花板"阻力位 |
| 最低点 | L | 前高之后的最低收盘价。代表市场认可的底部 |
| 横盘区 | C | 最低点之后的一段窄幅震荡。卖压耗尽、买盘在低位吸筹的阶段 |
| 突破日 1 | B1 | 横盘后首次放量突破。阳线、量比≥1.3、涨幅≥2%、突破 MA5 或 MA10 |
| 整理段 | P | B1 之后、B2 之前的短暂回踩或横盘。检验 B1 的有效性 |
| 突破日 2 | B2 | 脱离整理平台的二次放量突破。必须收盘价高于整理段最高点，确认趋势启动 |

### 1.4 参考案例

|------|------|------|------|------|------|:--:|

## 2. 结构节点自动识别

### 2.1 前高 (H) 识别算法

```
输入: K线数据 klines[start_idx .. end_idx]
输出: H 的索引和价格

算法:
1. 遍历区间内每一天 i
2. 取 klines[i]['high']（盘中最高价）
3. 判断局部峰值: hi >= max(klines[j]['high'] for j in range(i-40, i)) 且 hi > max(klines[j]['high'] for j in range(i+1, i+40))
4. 判断后续跌幅: (hi - min(future closes)) / hi ≥ 10%
5. 取满足条件的价格最高的点作为 H
6. 兜底: 无符合条件的局部峰值时，取区间前半段的最高盘中价

为什么用盘中最高价:
  前高代表"天花板"阻力位，盘中最高价才是市场曾经真正到过的高度。
  收盘价会低估这个天花板，尤其是高位横盘时（每天冲高回落，收盘总比盘中低）。

为什么用 40 天窗口:
  避免双顶结构误判（如中际旭创 12-25 峰值后 01-30 次高点，
  20 天窗口会将它们视为同一平台，40 天才能跨过看到后面的下跌）。
```

### 2.2 最低点 (L) 识别算法

```
输入: K线数据, H 索引
输出: L 的索引和价格（收盘价）

算法:
在前高和区间末尾之间，找最低收盘价。
用收盘价而非盘中最低价——盘中的恐慌尖针没有操作意义，
收盘价才是市场认可的底部。
```

### 2.3 横盘区 (C) 识别算法

```
输入: K线数据, L 索引
输出: C 的起止索引

算法:
1. 以最低点为起点
2. 向后扩展，维护当前区间的振幅 = (max - min) / min
3. 振幅 ≤ 10% → 继续扩展
4. 振幅 > 10% → 该日之前为横盘区终点
5. 横盘区 < 3 天时，放宽振幅到 15%
```

### 2.4 突破日 1 (B1) 识别算法

```
输入: K线数据, C_end 索引
输出: B1 的索引

算法:
从 C_end+1 开始向后扫描，找到第一个同时满足以下条件的交易日:
  1. 阳线 (close > open)
  2. 量比 ≥ 1.3 (当日量 / 20 日均量)
  3. 涨幅 ≥ 2%
  4. 收盘位置 ≥ 25%（跳空突破日常带上影线，放宽此约束）
  5. close > MA5 或 close > MA10

放宽路径:
  量比 ≥ 1.1, 涨幅 ≥ 1%, 不要求收盘位置和 MA
```

### 2.5 突破日 2 (B2) 识别算法

```
输入: K线数据, B1 索引
输出: B2 的索引

算法:
从 B1+1 开始向后扫描，找到第一个同时满足以下条件的交易日:
  1. 阳线
  2. 收盘价 > 整理平台最高点（核心约束——必须真正脱离整理区）
     整理平台最高点 = max(B1 最高价, B1 后至当日前的最高收盘价)
  3. 量比 ≥ 1.3
  4. 涨幅 ≥ 3%
  5. 收盘位置 ≥ 50%
  6. 额外加分: 突破 MA30 或 MA60, 或跳空高开

放宽路径:
  量比 ≥ 1.1, 涨幅 ≥ 2%, 收盘位置 ≥ 50%，平台突破约束不变
```

## 3. 量化特征体系

### 3.1 前高段 (H)

| 特征 | 字段 | 计算方式 |
|------|------|---------|
| 日期 | H_date | 前高所在交易日 |
| 价格 | H_price | 盘中最高价 |
| RPS_20 | H_rs20 | 前高日的全市场 RPS_20 |
| RPS_120 | H_rs120 | 前高日的全市场 RPS_120 |
| RPS_250 | H_rs250 | 前高日的全市场 RPS_250 |
| 行业 | H_industry | 所属申万二级行业 |
| 距 SMA50 | H_close_vs_sma50 | (当日收盘 - SMA50) / SMA50 |
| SMA50 斜率 | H_sma50_slope | (SMA50 - 10日前SMA50) / 10日前SMA50 |

### 3.2 调整段 (D)

| 特征 | 字段 | 计算方式 |
|------|------|---------|
| 跌幅 | D_decline_pct | (最低收盘 - 前高) / 前高，负值 |
| 下跌天数 | D_days | 前高日 → 最低日的交易日数 |
| 最大单日跌幅 | D_max_daily_drop | 调整段内最大单日涨跌幅，负值 |
| 日均成交量 | D_vol_avg | 调整段日均成交量 |

### 3.3 横盘段 (C)

| 特征 | 字段 | 计算方式 |
|------|------|---------|
| 横盘天数 | C_days | 横盘区首尾之间的交易日数 |
| 振幅 | C_amplitude_pct | (区间最高 - 区间最低) / 区间最低 |
| 低点斜率 | C_low_slope | 收盘价的线性回归斜率（正值=底部抬高） |
| 日均成交量 | C_vol_avg | 横盘段日均成交量 |
| 量萎缩比 | C_vol_vs_D | 横盘日均量 / 调整段日均量（<1 = 缩量横盘） |
| AD 斜率 | C_ad_slope | 收盘位置(close_pos)的线性回归斜率（近似 AD 线） |

### 3.4 突破日 1 (B1)

| 特征 | 字段 | 计算方式 |
|------|------|---------|
| 日期 | B1_date | B1 的交易日 |
| 涨幅 | B1_return_pct | 当日涨跌幅 % |
| 收盘位置 | B1_close_pos | (收盘 - 最低) / (最高 - 最低) |
| 成交量 | B1_vol | 当日成交量 |
| 量比(vs20) | B1_vol_ratio_vs_20d | 当日量 / 20 日均量 |
| 量比(vs50) | B1_vol_ratio_vs_50d | 当日量 / 50 日均量 |
| 量 vs 横盘最大量 | B1_vol_vs_C_max | 当日量 / 横盘期最大单日量 |
| 突破均线条数 | B1_ma_break_count | 突破 MA5/10/20/30/60 中的几条 |
| 创横盘新高 | B1_new_high_vs_C | 收盘是否高于横盘区最高价 |

### 3.5 整理段 (P)

| 特征 | 字段 | 计算方式 |
|------|------|---------|
| 整理天数 | P_days | B1 次日至 B2 前日的交易日数 |
| 最大回撤 | P_max_drawdown_pct | 相对 B1 收盘价的最大回撤，负值 |
| 守住 B1 低点 | P_held_b1_low | 是否所有整理日最低价 ≥ B1 最低价的 98% |
| 日均成交量 | P_vol_avg | 整理段日均成交量 |
| 量萎缩比 | P_vol_vs_B1 | 整理日均量 / B1 成交量（<1 = 缩量整理） |

### 3.6 突破日 2 (B2)

| 特征 | 字段 | 计算方式 |
|------|------|---------|
| 日期 | B2_date | B2 的交易日 |
| 涨幅 | B2_return_pct | 当日涨跌幅 % |
| 是否跳空 | B2_is_gap | 开盘 > 前日最高价 |
| 收盘位置 | B2_close_pos | (收盘 - 最低) / (最高 - 最低) |
| 成交量 | B2_vol | 当日成交量 |
| 量比(vs20) | B2_vol_ratio_vs_20d | 当日量 / 20 日均量 |
| 量比(vs50) | B2_vol_ratio_vs_50d | 当日量 / 50 日均量 |
| 量 vs B1 量 | B2_vol_vs_B1 | B2 量 / B1 量 |
| 突破均线条数 | B2_ma_break_count | 突破 MA5/10/20/30/60 中的几条 |
| 50 日新高 | B2_is_50d_high | 收盘是否 ≥ 过去 50 日最高收盘的 99% |

### 3.7 总体表现

| 特征 | 字段 | 计算方式 |
|------|------|---------|
| B1→期末收益 | total_return_B1_to_end | (区间末收盘 / B1 收盘 - 1) × 100% |

## 6. 当前状态与后续规划

### 6.1 当前状态

- ✅ 结构节点自动识别引擎（6 节点）
- ✅ 30 项量化特征计算
- ✅ Flask API 端点
- ✅ 前端录入页面（输入 + 案例持久化 + 结果展示）
- ✅ 三只参考案例验证通过

### 6.2 已知局限

1. **B1 识别精度**：对跳空高开带上影线的突破日，收盘位置约束需放宽到 25%，可能引入假阳性
2. **前高识别**：双顶/高位横盘结构可能导致前高日期与人工判断有偏差
3. **横盘区判定**：仅用振幅约束，可能将缓慢上升期误判为横盘
4. **均线依赖**：B1/B2 的均线突破条件依赖 MA5/10/20/30/60，次新股可能均线数据不足

### 6.3 后续方向

1. **积累案例**：人工录入更多已验证的形态案例，形成训练集
2. **特征分析**：对案例库的特征做统计分析，找出区分"成功形态"和"失败形态"的关键特征
3. **变成扫描引擎**：将结构识别逻辑从"给定日期范围"改为"全市场滑动窗口扫描"
4. **增加失败案例**：录入突破后回落的案例，让特征矩阵同时包含正负样本

## 7. 设计原则

1. **先积累后扫描**：不急于做自动扫描。用人工经验喂养引擎，让数据说话
2. **人工锚定日期**：起止日期由人提供，算法只负责在给定区间内识别结构——这保证了"正确答案"存在
3. **持久化案例库**：localStorage 保存，简单可靠，数据属于用户
4. **可解释性**：每个特征都有明确的物理含义，不引入黑箱指标
5. **迭代改进**：引擎规则基于三只案例调参，随着案例增加持续修正阈值
