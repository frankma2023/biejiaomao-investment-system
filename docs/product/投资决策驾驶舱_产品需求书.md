## 1. 产品概述

### 1.1 解决的问题

用户已拥有 13+ 个独立工具（MW 信号、口袋支点 V3、基部突破 V2、CAN SLIM 评分、RS 强度、指数扫描、缠论引擎等），但存在「决策支持断层」：信号系统给出了概率上最优的候选，但从信号到下单之间的黑箱里缺少锚定信息。实际操作流程是「外部信息源 → 单维度信号确认 → 冲动入场 → 机械止损」，五个维度的入场恐惧（胜率不确定、公司不了解、大盘不可控、仓位不会算、连续亏损打击信心）没有对应的计算来消解。

### 1.2 解决方案

**每日自动运行的决策驾驶舱**：硬过滤管道（5000+ → 3~5 只）+ 每只候选票的完整简报卡 + 五关下单前检查单 + 凯利仓位/动态止损建议。

设计哲学：不是替代用户判断，而是在用户最脆弱的那一步（信号已出、鼠标悬在买入键上）提供系统性的计算支撑，让「不敢下手」变成「算过之后选择不买」或「算过之后安心下单」。

### 1.3 用户角色

唯一用户：个人独立投资者，每日开盘前/盘中打开驾驶舱，从 3~5 只精选候选里挑票，参考简报后执行或放弃。

## 2. 系统架构

### 2.1 整体流程

```
每日 cron / daily_update.py 触发
  │
  ├─ Step 1: 硬过滤管道（逐级缩池）
  │    观察池 → 市值门槛 → 行业RS → 个股RS → 形态信号
  │    5000+ → ~600 → ~400 → ~200 → ~50 → 3~5
  │
  ├─ Step 2: 简报生成（每只候选）
  │    信号概要 + 胜率参考 + 基本面速览 + 行业背景
  │    + 大盘环境 + 仓位建议 + 外部舆情 + 欧奈尔分析
  │    + 止损/止盈建议
  │
  └─ Step 3: 结果持久化
       写入数据库 → 前端页面读取展示
```

### 2.2 核心认知：RS 强度与形态信号的时序错位

RS 强度高的时候股价在涨，信号不会出现（MW/口袋支点/基部突破都是回调中的信号）。信号出现的时候 RS 强度已回落。两者不能在同一时点做 AND 硬过滤。

**处理方式**：硬过滤中的「个股 RS 强度」取前高时点（H 点）的 RS250 值，而非当前 RS。形态信号本身已内嵌了「过去强势 + 当前回调」的时序结构。

## 3. 硬过滤管道

### 3.1 管道设计原则

- **串行逐级缩池**：前一级的输出是后一级的输入，避免无效计算
- **硬过滤 = 不通过直接踢掉**：不参与后续步骤，不进入候选
- **软排序在简报层做**：过了硬过滤的票，按软维度打分排先后（CAN SLIM 评分、缠论信号共振、大盘匹配度等）

### 3.2 五级管道详细规则

#### 第一级：观察池过滤

| 项目 | 说明 |
|------|------|
| 数据源 | `discipline/observation.html` 对应的数据（RS 强度筛选产出） |
| 逻辑 | 股票同时存在于三类池（双强股 / 稳健龙头 / 加速爆发）中任一类，即通过 |
| 效果 | 5000+ → ~600 |
| 备注 | 观察池由 RS 引擎每日更新，取最新日期数据 |

#### 第二级：市值门槛（v2.0 市值快照表）

| 项目 | 说明 |
|------|------|
| 条件 | 总市值 ≥ 50 亿 |
| 数据源 | `market_cap_snapshot` 快照表（每日盘后由 `market_cap_snapshot.py` 预计算） |
| 效果 | ~600 → ~400 |
| 备注 | 快照表覆盖观察池 ~400~600 只股票，秒级查询。市值数据来源：pysnowball `quotec()` 的 `market_capital` 字段（实时），或 fundamental_indicator 的 `mc` 指标（异步回填）。快照表为空时全部通过（不阻塞管道） |

#### 第三级：行业 RS 强度

| 项目 | 说明 |
|------|------|
| 条件 | 股票所属行业（L2 优先，L1 兜底）指数 RS250 ≥ 75 |
| 数据源 | 中证 L1/L2 行业指数的 RS 值 |
| 效果 | ~400 → ~200 |
| 备注 | 逆风行业不碰。不属于任何中证行业的股票降权（可保留但标记"行业未知"） |

#### 第四级：个股 RS 强度（历史时点）

| 项目 | 说明 |
|------|------|
| 条件 | 股票在其形态信号的「前高时点」（H 点）RS250 ≥ 80 |
| 数据源 | `stock_rs_daily` 表，取 H 日期的 RPS_250 |
| 效果 | ~200 → ~50 |
| 备注 | 若该票有 MW 信号则取 `h_rs250` 字段；口袋支点取 H 日；基部突破取突破前最近高点。若无 H 点（纯趋势跟随型信号），取最近 60 天内最高 RS250 |

#### 第五级：形态信号

| 项目 | 说明 |
|------|------|
| 条件 | 在最近 N 个自然日内（默认 5 天），至少出现以下任一信号 |
| 数据源 | `mw_signal_daily`（PLUS 优先）、`pocket_pivot_v3_daily`、`base_breakout_v2_daily` |
| 效果 | ~50 → 3~5 |
| 排序 | 按信号优先级：PLUS（score≥80）> 口袋支点 B1 重合 > 基部突破 V2 > MW B2 > 纯口袋支点 |

#### 3.3 管道可配置参数

所有阈值参数存入 `config/cockpit.yaml`，前端可调整。

> ⚠ **配置持久化铁律**：遵循全站回测看板标准。前端「保存配置」按钮 → POST 参数到 `/api/cockpit/config` → 写入 `config/cockpit.yaml`。页面初始化时 → GET 配置文件 → 填充所有参数控件。参数流通路径：`config/cockpit.yaml` ↔ API ↔ 前端控件 ↔ 管道引擎。违反此规则视为未完成。

```yaml
pipeline:
  market_cap_min: 50              # 亿
  industry_rs250_min: 75
  stock_rs250_h_min: 80
  signal_lookback_days: 5
  max_candidates: 5
position:
  max_loss_pct: 0.02              # 单笔最大亏损占账户 %
  kelly_fraction: 0.25            # 凯利公式分数（1/4凯利）
  account_size: 1000000           # 账户总资产（用户可改）
```

### 4.8 欧奈尔分析（v2.0 双层架构）

#### 第一层：规则引擎快速评估（`oneil_eval.py`）

基于 trade-like-oneil 技能的 8 条核心规则，使用 if-else 结构化打分，生成 10 行快速评估。每次管道运行自动执行，结果写入数据库 `cockpit_daily.oneil_analysis` 字段，前端简报区即时展示。

| 规则 | 评估逻辑 |
|------|------|
| 规则1 高价股 | 入场价 ≥20 元为合格 |
| 规则3 止损空间 | 止损幅度 ≤10% 为可控 |
| 规则5 头寸集中 | 默认通过，建议单票 15~25% |
| 规则6 机构认同 | CANSLIM-I ≥50 为合格 |
| 规则7 图表形态 | 有强信号（mw_plus/base_breakout/pocket_pivot_b1）为通过 |
| 规则8 口袋支点 | 有口袋支点或 B1 重合或 PLUS 信号为通过 |
| 规则9 市场择时 | 大盘绿灯或黄灯 + 抛盘日<5 为通过 |
| 规则10 龙头股 | RS250≥85 + CANSLIM≥60 双满足为龙头 |

综合评分：通过数/8 × 100，≥85 推荐买入，≥60 谨慎买入，≥40 观望，<40 不建议。

#### 第二层：DeepSeek 深度分析（`oneil_deep.py`）

对前 5 只候选，在管道运行期间调用 DeepSeek CLI（`D:\dstui\deepseek-tui-windows-x64.exe`），将 trade-like-oneil 技能的完整 SKILL.md（前 2000 字）作为系统指令，输入股票全维度数据，生成 1000+ 字 HTML 深度分析报告。

**实现架构**：管道预生成 + 按需降级

```
管道运行(save_candidates)
  └─ _generate_oneil_deep()
       ├─ 采集全维度数据
       ├─ 构建 prompt（技能框架 + 股票数据）
       ├─ subprocess.run([deepseek-tui, '-p', prompt])
       └─ 保存到 data/cockpit/oneil/{date}/{code}.html

前端点击
  ├─ 优先: GET /api/cockpit/oneil-report → 返回预生成 HTML（秒开）
  └─ 降级: GET /api/cockpit/oneil-deep → 实时 CLI 生成（30~60秒）
```

> 与 screening.html「欧奈尔说」共用同一个 DeepSeek CLI 可执行文件，架构统一。

**输入数据（全维度）**：

| 数据类别 | 具体内容 |
|------|------|
| MW 信号 | B1/B2 日期、评分、PLUS 标识、置信度、H/L 点价格、调整深度、维度分(H/D/C/P/I1/I2) |

| 基部突破 | 近 10 日信号（日期、涨幅） |
| CAN SLIM | 总分 + 七维度分项 + ROE + EPS 增速 |
| 涨跌量趋势 | 近 5/10/20 日累计涨跌幅 + 均量 + 放量/缩量趋势 + 近 10 日逐日涨跌 |
| K 线形态 | TA-Lib 13 种形态（吞没/锤子线/启明星/黄昏星/孕线/刺透/乌云盖顶/射击之星/倒锤子/三白兵/三只乌鸦/光头光脚/十字星），含日期和 OHLC |

| 行业背景 | 中证一级行业名称 + 行业 RS250 |
| 大盘环境 | 红绿灯、近 30 日抛盘日/吸筹日/追盘日数量、市场健康分/风险等级、卖出评分/信号 |

**输出格式**：深色主题 HTML 页面，含标题层级、粗体要点、买卖建议标签（绿色推荐/橙色谨慎/灰色观望/红色不建议）。

## 6. 仓位计算引擎

### 6.1 核心算法：最大亏损倒推法

```
单笔最大亏损金额 = 账户总资产 × max_loss_pct（默认 2%）
止损幅度         = (入场价 - 止损价) / 入场价
建议仓位金额     = 单笔最大亏损金额 / 止损幅度
建议仓位 %       = 建议仓位金额 / 账户总资产
```

### 6.2 凯利公式（软参考上限）

```
凯利仓位 = (p × b - (1-p)) / b
其中: p = 该信号类型历史胜率
      b = 历史平均盈利 / 历史平均亏损（绝对值）

实际软上限 = 凯利仓位 × kelly_fraction（默认 0.25，即四分一凯利）
```

**回测数据不足时的 fallback**：若该信号类型无回测数据（如基部突破 V2 回测未全量、口袋支点 V3 回测未全量），凯利软上限不启用。仅显示最大亏损倒推仓位，标注「⚠ 凯利：回测数据不足，未启用软上限」。不影响最大亏损倒推法的仓位计算。

### 6.3 仓位决策逻辑

```
IF 建议仓位% ≤ 凯利软上限:
    显示建议仓位%，绿色
ELIF 建议仓位% > 凯利软上限:
    显示凯利软上限，黄色警告「超过凯利参考上限，已自动限制」
    同时显示原始计算值供参考
```

### 6.4 当前总仓位约束

从 `monitor.html` 的数据获取当前持仓总仓位。若已满仓（≥95%），所有新建议仓位显示 0 并提示「当前已接近满仓，建议等待现有持仓退出后再开新仓」。

## 7. 止损/止盈逻辑

### 7.1 初始止损

| 信号类型 | 止损位 | 逻辑 |
|------|------|------|
| MW PLUS / MW B2 | B2 日最低价 | 突破确认日的最低点 = 资金防守线 |
| 口袋支点 V3（base） | 信号日最低价 | 启动日的最低点 = 盘整区下沿 |
| 口袋支点 V3（continuation） | 10 日均线值 | 延续型回踩均线，均线 = 支撑 |
| 基部突破 V2 | 基部下沿（L 日最低价） | 基部下沿 = 结构支撑 |
| 多信号重叠 | 取最紧的止损位 | 多个信号取最严格的止损 |

### 7.2 移动止损（V1 实现）

| 条件 | 动作 |
|------|------|
| 浮盈 ≥ 5% | 止损线上移至成本价（保本损） |
| 浮盈 ≥ 10% | 止损线跟踪：`max(当前价 × (1 - 2×ATR%), 成本价)` |
| 浮盈 ≥ 20% | 止损线跟踪：`max(当前价 × (1 - 3×ATR%), 10 日均线)` |

ATR 取 14 日平均真实波幅。

### 7.3 止盈参考

第一目标位 = H 点价格（前高）。不设强制止盈，仅作为参考标注。

## 16. 已知局限

1. **回测数据时效**：MW PLUS 仅 5 个月回测数据，口袋支点和基部突破回测尚未跑全量，胜率参考需标注数据范围
2. **行业映射覆盖**：仅约 38% 的股票能映射到中证 L1/L2 行业，未被覆盖的票行业 RS 维度降权
3. **市值快照**：市值字段当前多为 NULL（依赖 pysnowball 回填或 fundamental_indicator 异步更新），管道暂按"未知=通过"处理
4. **DeepSeek 分析耗时**：每只股票 CLI 调用约 30~60 秒，5 只约 3~5 分钟。管道总耗时约 5~8 分钟。前端打开即加载预生成缓存，秒开
5. **DeepSeek CLI 依赖**：需要 `D:\dstui\deepseek-tui-windows-x64.exe` 可执行文件存在，与 screening.html「欧奈尔说」共用
6. **管道顺序假设**：当前五级顺序是基于逻辑推演而非数据验证的最优序，后续可根据实际缩池效率调整
7. **仓位约束**：凯利公式假设收益分布稳定，但不适用于回测数据有限的场景（已用四分一凯利缓解）
