# 基部突破检测引擎 V2 · 产品需求书

> 版本：v2.0 | 日期：2026-06-10 | 状态：✅ 已实现  
> 代码文件：`src/scanners/base_breakout_v2.py`  
> 引擎名称：`base_breakout_v2`  
> 参考：威廉·欧奈尔《笑傲股市》基部突破买入规则 + 缠论结构驱动

---

## 1. 产品概述

### 1.1 信号定义

识别 A 股市场中「强势股经充分回调后形成基部，放量突破枢轴点」的买入信号。核心逻辑：**缠论 H/L/C 结构定位基部上下沿 + 欧奈尔经典突破规则逐日扫描**。

### 1.2 设计理念

- **不属于口袋支点**：不检查「量 > 前10天最大下跌量」「盘整量能萎缩」等口袋支点专属条件，避免与 `pocket_pivot_v2.py` 职责重叠
- **单一 BO 突破信号**：在 C 区（盘整区）内逐日扫描，满足全部条件的那一天即为突破日。每个 C 区最多产出一个信号
- **欧奈尔规则驱动**：回撤深度、量比、涨幅、MA60 等条件直接对齐欧奈尔原著
- **缠论定位**：H（前高）和 L（低点）优先从 MW 信号表获取，其次从缠论 bi 峰谷检测。不依赖固定窗口参数

### 1.3 与 V1 的关键区别

| 项目 | V1 | V2 |
|------|------|------|
| H/L 定位 | 局部窗口法 `find_peaks_troughs()` | MW 信号表 → 缠论 bi 峰谷 |
| C 区间 | 自研振幅窗口 | 缠论定义（L 之后到当前） |
| 信号类型 | 多级评分 | 单一 BO 通过/不通过 |
| MA 检查 | MA10 > MA20（硬性） | MA60（硬性），MA10≥MA20（标记） |
| 量能条件 | 自研量比体系 | 20日均量 × 1.5 |
| 参数来源 | 经验调参 | 对齐欧奈尔原著 |

## 2. 判定规则

### 2.1 前置过滤（全部满足才进入扫描）

| # | 条件 | 阈值 | 欧奈尔依据 |
|:--:|------|:--:|------|
| F1 | K 线数量 | ≥ 120 根 | 足够的历史数据计算 MA60 |
| F2 | H/L/C 结构 | MW 信号表（跳过 H/L 同日）→ 缠论 bi 兜底 | 精确的基部边界 |
| F3 | **回撤深度** | **8% ≤ decline ≤ 40%** | 充分洗盘但未破坏趋势 |
| F4 | **盘整天数** | **≥ 20 天（4 周）** | 欧奈尔要求 7~8 周，A 股放宽至 4 周 |
| F5 | C 区早期振幅 | ≤ 15%（仅检查前 40 天） | 盘整区应安静，非宽幅震荡 |

### 2.2 逐日扫描（全部满足才产出信号）

| # | 条件 | 阈值 | 含义 |
|:--:|------|:--:|------|
| D1 | **涨幅** | 当日相对前日收盘 **≥ 3%** | 有效突破，不是小阳线蹭过去 |
| D2 | **放量** | 当日量 ≥ 20日均量 × **1.5** | 机构资金进场确认 |
| D3 | **收盘质量** | 收盘在日内位置 ≥ **50%** | 不是尾盘跳水，买盘持续到收盘 |
| D4 | **站上 MA10** | 收盘 > MA10 | 短期趋势向上 |
| D5 | **站上 MA20** | 收盘 > MA20 | 中期趋势确认 |
| D6 | **站上 MA60** | 收盘 > MA60 | 🔑 欧奈尔 50 日线规则（A 股用 60 日） |
| D7 | **不延伸过度** | 收盘 ≤ MA10 × **1.30** | 不追高，距 10 日线不超过 30% |
| D8 | **突破 C 区** | 收盘 > C 区（到当前日前一天）最高收盘价 | 脱离盘整区，创新高 |
| D9 | **突破阻力** | 当日最高 ≥ 前 10 天最高 | 突破近期套牢盘 |
| D10 | **RS 强度** | rps20 ≥ 80 **且** rps250 ≥ 80（仅当 RS 数据可用时） | 强势股确认 |

### 2.3 非硬性门禁（标记但不拒绝）

| 条件 | 输出字段 | 含义 |
|------|------|------|
| MA10 ≥ MA20 | `ma10_cross_ma20: true/false` | 短期均线已金叉，信号更强 |
| 距前高位置 | `prior_high_price` | 用于人工判断是否接近新高 |

## 3. 信号输出

| 字段 | 含义 |
|------|------|
| `signal_date` | 突破日日期 |
| `prior_high_date` / `prior_high_price` | 前高 H 的日期和价格 |
| `trough_date` / `trough_price` | 低点 L 的日期和价格 |
| `drawdown_pct` | H→L 回撤深度（%） |
| `base_days` | C 区（盘整）天数 |
| `c_amplitude` | C 区早期振幅（%） |
| `breakout_close` | 突破日收盘价 |
| `breakout_gain_pct` | 突破日涨幅（%） |
| `breakout_vol_ratio` | 突破日量比（vs 20日均量） |
| `close_position` | 收盘在日内位置（0~1） |
| `ma10` / `ma20` / `ma60` | 当日均线值 |
| `ma10_cross_ma20` | MA10 是否高于 MA20（加分项） |
| `rps_20` / `rps_250` | RS 强度（如有） |
| `buy_point` | 枢轴点买入价（C 区最高收盘价 + 0.01） |

## 4. 数据依赖

| 数据 | 来源 | 说明 |
|------|------|------|
| H/L/C 结构 | `mw_signal_daily` 表（优先），`chanlun_scan_daily.bi_json`（兜底） | 缠论笔定位 |
| K 线 | `daily_kline` | OHLCV |
| RS | `stock_rs_daily` | RPS20/250（K线数据中注入） |

### 4.1 H/L/C 获取策略

1. 从 `mw_signal_daily` 取最近 5 个信号，跳过 `h_date >= l_date`（同日）的行，取第一个有效的
2. 若无 MW 信号，降级到 `chanlun_structure` → `get_bi_peaks()` 取最近的峰，再找峰后的最低收盘价作为 L

## 5. 参数配置

```yaml
# config/market/base_breakout_v2.yaml
base_breakout:
  drawdown_min: 0.08        # 最小调整深度 8%
  drawdown_max: 0.40        # 最大调整深度 40%
  min_c_days: 20            # 盘整最少天数
  c_amp_max: 0.15           # C区最大振幅
  bo_gain_min: 0.03         # 突破日最低涨幅 3%
  bo_vol_ratio: 1.5         # 量比（vs 20日均量）
  bo_close_pos_min: 0.50    # 收盘位置
  require_ma60: true        # 要求收盘 > MA60
  rs_threshold: 80          # RS最低阈值
  max_extension_pct: 0.30   # 距MA10最大延伸
```

## 6. 已知局限

1. **盘整天数**：欧奈尔要求 7~8 周（35~40 天），A 股放宽至 20 天。更短的基部可能被漏掉
2. **大盘配合未实现**：欧奈尔要求大盘处于上升趋势（追盘日已确认），当前引擎不做大盘判断
3. **RS 数据依赖**：`stock_rs_daily` 最早为 2026-05-08，早期 K 线无 RS 时 D10 自动跳过
4. **H/L 同日问题**：MW 信号表中存在 H 和 L 同日的记录（调整不充分），已跳过但仍依赖 MW 表数据质量
5. **与 V1 共存**：pattern-scan 同时显示 V1 和 V2 信号，待 V2 验证后下线 V1
